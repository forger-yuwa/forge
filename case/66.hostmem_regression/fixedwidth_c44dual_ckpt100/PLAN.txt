7. 評価法 (fixedwidth_eval.py eval)
   新しい各 run X (b 6 本・n 6 本) について、既存 base 3 本 B1–B3 と比べる:
   - 構造: 出力ファイル集合、各 h5 のデータセット集合・shape・dtype・属性 (/CHECKPOINT の totalTime・dt・nHistoryValid 等
     = 物理時刻を含む) が B1 と厳密一致。
   - 行キー: residual_history.csv の (step, inner, phase) の列が B1 と厳密一致。
   - 初期出力 (res_0.h5) の保存量・原始量・幾何量、整数の量 (MESH/CONNE): B1 とビット一致。
   - 幅の量: v = max_i ||X − B_i||_∞ ≤ T (同じ T を全 run に)。差 0 を要求する量は v = 0。
   - 非有限・shape 違い・欠落は失敗 (PASS にしない)。NANCHECK.txt も PASS であること。
   b と n を分けて集計し、下の判定表で決める。
   評価スクリプトの確認 (段階 1、new は使っていない): 既存 base 3 本を評価対象にすると全量幅内・構造一致 (定義上そうなる)。
   B1 の出力の複製に人工の差 (ro に +1、差 0 を要求する roK を変更、T に NaN、初期出力 P に 1 ULP) を入れると 4 件とも検出
   (幅超過 2・比較不能 1・初期出力の不一致 1)。本数が b 6・n 6 でないときは「判定不能」を返す。

8. 判定表 (plan §6.3)
   | 結果                              | 判定                                                                             |
   | 新規 base・new とも全量で幅内      | 「追加標本でもこの固定幅を超える差は検出されなかった」— 限定した支持材料として result レビューへ |
   | 新規 base は幅内、new だけ超過     | 変更起因の差を優先して追う (諮る)                                                  |
   | 新規 base も超過                   | 基準 3 本では再現性を捉えられていない → 判定不能 (その場で T や反復数を増やして合格にしない) |
   全量が幅内でも包括的な同等性は宣言しない (物理的に許せる誤差の上限は未定義)。
   事前の事実 (notes.txt §2(c)): condClampCorrQ_0 が 1.45〜1.46e23 になる節点 19954 の状態は、変更前バイナリの run_0077
   (c44dual_pindiag base r3) にも出ている。凍結した T はこの状態を含まない base 3 本から決まっている。
