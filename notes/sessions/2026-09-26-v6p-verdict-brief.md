## 3. 諮りたいこと

1. **V6′ を PASS と書いてよいか。** `eval_v6p.py` は 6 条件すべて PASS で事前予測の内側だが、
   **`check_convergence` と G-if がともに NOT CONVERGED**。登録は「流体残差は NOT CONVERGED になりうるので
   **界面ゲート + 準定常で判定する**」だが、**その界面ゲート (G-if) 自体が落ちている**。
   **PASS / 条件つき / FAIL / 判定不能 のどれで書くべきか 1 つに絞ってほしい。**
2. **G-if の扱い。** 登録では「全域 G-if は報告項目、判定範囲は帯」としたが、**帯内 G-if を測る実装が無い**
   (節点ごとの界面残差が `conjugate_history.csv` に出ず、`check_cht_interface.py` に帯オプションも無い)。
   **測れないものを「範囲を帯に限る」と登録したのは不備ではないか。** どう記録するのが正しいか。
   ①② が lip 行のリップルに支配されるのは float32 run で確認済み (伝達差が $y$=−0.777 mm で 51 %、
   −2.05 mm で 0.1 % 未満)。
3. **`check_quasisteady` をツールで回していない。** 帯平均の時系列は手で出した (上の数値)。
   AGENTS.md は「派生量を報告する応答にはこのツールの VERDICT を貼れ」と定めている。
   **帯平均という量にツールをどう当てるか** (ツールは run 直下の `res_*.h5` から既定の量を出す)。
   実装が要るなら何が最小か。
4. **$K$/$D_f$ 感度の読み方。** 登録は「帯内 $T_{w1}$ 差 ≤0.5 % of 固体上昇・$q$ 差 ≤0.5 %」だが
   **4 run のどれを基準に差を取るか書いていない** (§2.1 は各 run の解析解との差を出したもの)。
   基準を `Df_scale` 5 / `interval` 50 にしてよいか。また **`Df_scale` 20 / `interval` 200 が 5 倍大きい**のを
   「更新回数 1/4 で漸近の途中」と読んでよいか、それとも $D_f$ を上げすぎた副作用か。
5. **見落としの指摘。** 特に (i) 固体格子収束 ($n_l$) を振っていない — V6′ の登録に無いが必要か、
   (ii) `run_0010` は `run_0009` (float32) の場から継続しているので**種が float32** である点、
   (iii) `plate` を断熱にした変更が漸近解に影響しないことの確認をしていない点。

**両論併記で逃げず、それぞれ推奨を 1 つに絞ってほしい。根拠は `ファイル:行` か上の数値で示すこと。**
