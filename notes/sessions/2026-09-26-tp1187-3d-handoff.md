## 1. 前セッションで確定した事実 (再調査不要)

### 1-a. 原報から読み取った一次情報

- **90° 配列は位置 II (前縁 188 cm)。位置 II では層流データが取れず乱流のみ。**
- **データ整理** (p.7 逐語): 解析時刻 = 模型がトンネル中心線に達した時刻 = 挿入から **2 秒強**。
  dT/dt は **0.25 秒区間で温度を平均し区間間の差**。最大の温度上昇率は中心線到達より**前**に起きる
  (露出はステップでなく傾斜)。「伝導・放射損失 2 % 未満」は**平滑校正板**の評価。
- **L30/L15 比は統制された比較**: p.5「two instrumented thin-wall tiles」+ Fig 5「L=30.48 は番号 +25」
  より、**1 枚のパネルに L=15.24 と L=30.48 の計測タイルが両方載り、同一 run (8/14) で同時に測られている**。
  p.12 の「δ* の違いが唯一の差」は **90° vs 60/75° の比較**についての記述であって L 比較の話ではない
  (前セッションでこれを取り違えて「D4 無効」と書きかけ、自分で訂正した)。
- **乱流 90° は 3 次元**: p.11「The isometric heating rate contours indicate that the flow is
  three-dimensional. ... at least three gap widths」。p.10 の「W ≤ 0.18 cm では主に 2 次元」は
  **層流 60/75° の等値線の話**なので乱流 90° に持ち込まない (2D を決定実験に使わない)。
- **Fig 5 側面図の寸法** (図中に明記、digitize ではない): 前向き壁 TC92/91/90/89/88/87 =
  深さ **0.25 / 0.51 / 0.76 / 1.52 / 2.54 / 3.81 cm**。上面は 95/96 が角の直近、97 が 96 から 1.02、
  以降 1.52 / 1.52 / 1.91。**TC93 は円弧途中、TC94 は上面接点側、TC95 はその下流**
  (codex の読みと一致)。**93/94 は基準点が図から一意に読めず ±0.25 cm の不確かさが残る**ので
  2 通りの位置を併記して区間で抽出する。**TC89 (1.52 cm) は L=15.24 側の Table III(c) に無く
  L=30.48 側 (114) にだけある。**
- p.5–6 の **±0.03 cm は中心線に対するばらつき**であって帯測定ではない。
  模型設置時に「thermocouple center line with the upstream longitudinal gap center line」を合わせている
  → **帯平均 (z≤6 mm) ではなく中心線 (z=0) へ補間する**。

### 1-b. 独立に測った 2 件 (D1 の原因候補を減らす)

- **入口 BL は合っている**: `run_0002_fp_t8_long` の圧縮性 δ* は x=1.8797 m (= 位置 II) で
  **1.6625 cm**、原報 1.62 cm に **+2.6 %** (3 スナップショットで定常)。
  ただし原報 p.8 の δ* は **ref.6 由来の計算値**で直接測定ではない。
- **分母のずれは forge の欠陥ではない**: forge の 2D 平板 q_FP = 77.34 vs 実測 63.44 kW/m² = +21.9 %。
  原報 p.8 が「turbulent boundary-layer theory to be approximately 30 percent higher than the
  interpolated experimental data」と書いており +21.9 % はその内側 (実測寄り)。
  **forge 自身の分母で正規化すると TC93 は 1.261 とさらに下がるので、D1 不合格は分母のアーチファクトではない。**
  ただしこれは**誤差帯として不足分を許容する根拠にも、forge に欠陥が無い証明にもならない** (codex)。

## 2. 直した欠陥 (commit 済み)

- **M1 段の引き継ぎ**: `make_case3d.py` が段ごとに `restart_field.py` で出力を次段の入力へ移すようにした
  (`2c8e6fb7`)。`run_0065_L15_v2` で **7 段すべて `VERDICT: OK`**、`res_0` の `roUy` が
  1,423,413/1,483,495 節点で非ゼロ = 連結を実測で確認済み。
- **M9 破壊的な再実行**: 計算済み run があれば削除前に失敗させる。
- **y1/z1 の結合**: 生成器に `--z1` を足して**壁法線 y の刻みと縦すきま z の刻みを分離**した。
  同じ値が 2 つの仕事を兼ねていたため y1 を細かくすると AR が倍になっていた。
  平板の y1+ >1 が 98.1 %→**0.8 %**、gap 12.0 %→**7.3 %** (節点数・AR は据え置き)。

## 3. 未解決の欠陥 (次セッションが直す)

### 3-a. **L30 腕の入口が間違っている (最重要)**

`extract_inlet_table.py` の規約は「照合点 (x=0) で δ* が位置 II (1.88 m) と揃うよう平板の
**1.88 − |x_in|** を抜く」。メッシュの実 x 範囲を測ると:

| メッシュ | x_in | 正しい抽出 | 使用 |
|---|---|---|---|
| `gap3d_c50b`, `gap3d_c50b_v2` (L15) | −172.400 mm | 1.7076 m | 1.7076 ✓ |
| `gap3d_c50b_L30`, `gap3d_c50b_L30_v2` | **−324.800 mm** | **1.5552 m** | 1.7076 ✗ |

→ L30 腕は照合点で δ* が **1.80 cm** = L15 腕 1.66 cm より **+8.4 % 厚い**。
原報 p.12「heating decreases with increases in δ*」より**比を下げる向きの人工的交絡**で、
観測された不一致と同じ向き。**`run_0064_ab3d_L30_long` の D4 は無効**、
`run_0066_L30_v2` は梯子 3/7 段で**停止・破棄**した。

### 3-b. 観測モデル (`case/56.gap_tp1187/tools/skin_forward3d.py`) が測定手順と違う

- `:99–115` が一定熱流束を **0.25 s** 与えて終了時の**瞬時微分**を返す
  (原報は解析時刻 ≈2 s・0.25 s 区間平均の**区間間差分**)。
- `:32` の `TOP_TC` は番号対応がずれ **TC95 が欠落**。
- `:76` の節点平均は中心線の局所測定でなく、非一様格子を**等重み**平均しており面積平均でもない。

### 3-c. 壁解像が FAIL のまま

`check_wall_resolution.py --target 1 --over-frac 0` は `run_0065_L15_v2` で **FAIL**
(gap の 7.3 %、平板 0.8 %)。**超過はすべて「円弧/口」領域に局在**し、節点基準では
438/49,494 (0.9 %)・最大 3.3、上位は**縦すきま口の鋭いエッジ** (x=−149.90 mm, z≈0.9–1.0 mm)。
これは生成器が省略しているエッジ半径 (codex M7) そのもの。
**ツールの `over` は面積割合でなく点数割合** (`check_wall_resolution.py:369`)。
ツールの最大 243.7 と自作集計の 3.3 の差は、鋭いエッジで壁法線が一意でないため
「法線方向の第一内点」が対岸の節点を拾うため (**場所については両者一致**)。
**例外扱いは codex が却下した** — 実験に無い特異点を理由に検証要件を免除できない。

### 3-d. 局所量の準定常が未確認

`run_0064_ab3d_L30_long` を `check_quasisteady.py --series-csv _ab_series.csv
--series-cols q_tc92,q_tc91,q_tc90,q0_tc92,q0_tc91,q0_tc90` で再判定すると
**`OVERALL: NOT ALL STEADY`** — 帯平均 (`q_*`) は全列 STEADY だが
**中心線 `q0_tc90` が `DRIFTING`** (drift 17.7 %/tail、fluct 44.1 %)。
**その末尾平均は +0.5496 W/m² で他列 (負) と符号が逆の実質ゼロ**なので、
**比 0.0197 はゼロ割に近く有効数字を持たない**。
**帯平均の ALL STEADY を局所観測量へ移用できない** (前セッションは帯平均で D4 を主張していた)。

## 4. 次の一手 (codex 推奨の順。plan §5.1 #60 の末尾と同じ)

1. **座標台帳・局所抽出・時間窓を固定した観測モデルを `skin_forward3d.py` に実装**する。
   - 入力は符号を統一した定常熱流束 q₀(s,z)。加熱は q = a(t)·q₀ (分離形は近似であり、
     挿入中の流れを再現したとは呼ばない)。
   - 薄板は**面内伝導つき** ρcτ ∂T/∂t = ∇ₛ·(λτ∇ₛT) + a(t)q₀。
     √(αt) ≈ 2.76 mm (2 s) なので **6 mm 帯を先に平均して 1 次元化しない**。
   - Δ = 0.25 s、共通境界時刻 t_a の前後の区間平均から
     **q̂ = ρcτ(T̄₊ − T̄₋)/Δ を各 TC 位置で**評価する。
   - **主腕 = ステップ露出、副腕 = 同じ開始時刻から t_a までの線形ランプ**。暫定 t_a = 2 s。
     材料値・座標・時刻・窓は全 TC と両 L で共通とし、実測への当てはめで変更しない。
2. **CFD を追加実行せず**、`run_0065_L15_v2` の保存場で**露出履歴だけ**を切り替える後処理 A/B。
   - 判定が変わる → 「履歴を確定せず D1 を確定できる」という前提を棄却。
   - 変わらない → このステップ/ランプ差を判定変更の説明から外す。
3. **観測後の量も `check_quasisteady` にかける** (生の局所 q の判定とは別)。
4. **L30 腕は入口テーブルを 1.5552 m で作り直してから**再投入 (D4 用)。
5. **Version B (縦すきま口のエッジ半径)** で 3-c と codex M7 を同時に解消。
   断面が z 依存で変形するため生成器の作り直しに相当する (数日規模)。

## 5. やらない方がよいこと (codex が明示)

- `--t 2` だけ変更し、**TC90 の比 (0.537) を根拠に観測モデルを確定すること**。
  「時間演算で物理的に説明できた」と言うには、**単一の履歴で**次を同時に満たす必要がある:
  両 L の TC90/91/92 の絶対加熱量と深さ分布 / 修正座標での TC93/94/95 のピーク位置と上面減衰 /
  D4 の複数点の比。**点ごとに別の履歴を選んだ包絡線で合格させない。**
  なお台帳の原数値では TC90 の帯下端は **1.49/2.77 = 0.537906…** なので、丸めた 0.537 から
  「区間内」とは判定できない (**未丸め値で比較する**)。
- **壁解像の最大値が特異点にあるという理由だけで FAIL を免除すること。**
  7.3 % と自作集計 0.9 % は評価対象・分母を揃えないと比較できない。
- **原報の「縦すきま長に沿う周期的加熱パターン」を、時間的非定常や定常 RANS の限界の証明にすること。**
  原報 index 12 が述べるのは、まず**空間的な長さ依存**である。
- **D4 を D1 の代替合格にすること** (`acceptance.json` が「D1 合格後の条件付き」と事前登録)。
  診断目的で先に D4 を見るのはよい。

  **諮る前に毎回このファイルを確認すること** (前セッションはこれを飛ばして Fable を呼び、
  usage 上限で失敗した)。諮問は
  `python3 solver_density_cuda/tools/codex_review.py --stage diagnose --brief <brief.md> [plan]`、
  ブリーフは `notes/reviews/briefs/<日付>-<slug>.md`、`run_in_background` + timeout 1200 s 以上。

  status/busy を見てから触る。手動 stop はしない)。ローカルは数秒の切り分けだけ。
- **`FORGE_CUDA_BLOCKSIZE=128` を必ず揃える** (既定 512 は node SLAU のレジスタ上限 481 を超えて
  起動不能。**この値は結果に効く**)。
- 別ワークツリー `forge-cht/` で**他セッションが並行作業している**。あちらの run・plan に触らない。
