## 1 行で

**定常陰解法の `Q = Q_N + dq` が float32 の丸めで止まる問題**に、保存量 5 本の FP64 正本を足して直した。
v1a は閉じた。**後続 (横展開) は codex plan レビュー 2 回とも NO-GO で、実装に入っていない。**

## v1a で何ができたか

`case/56` の深いすきまで、素の float32 が作っていた **偽の入熱** ($q_w$ が 2 W/m² に張り付く) と
**偽の下降流** (1.5e-2 m/s) が消え、全域 FP64 と一致した (深さ 5 倍まで 0.00–3.77 %)。
費用 40.0 B/CV、速度は 65k CV で +1.77 % / 100 万節点で +2.05 % (片側 95 % 上限)。

**できていないこと**: 計算が収束するようになったわけではない。残差プラトーは倍精度と同じで、
直ったのは**局所停滞と過渡減衰**だけ。

## 使い方

`time.deltaT.qAccumulatorFP64: 1` (**`time:` 直下ではない**。既定 0)。
対応は **GPU・node・`tI=11`・`unsteady=0`・軸対称なし・周期なし・`sstEnergyIncludesK=0`** のみ。
**それ以外は起動時に拒否する** (何待ちかをログに出す)。
**乱流・化学種・凝縮モーメント・トレーサ・遷移モデルは累積対象外**で、起動時に列挙して警告する。

## 次にやること (後続 plan §5.1 / §6.0)

**実装の前に plan の設計を詰める**。codex が 2 回とも NO-GO にした理由:

1. **検証表 (§6.0) に空欄がある** — #7 の許容値、RK3 の刻み幅・誤差ノルム・次数許容、
   dual-time の BDF1 と restart、`tI=1` の試験、`tI=4` の A、RK3/dual-time の R、
   周期×SST×積分器の組合せ。**「全項目で同一 SHA」は回帰ゲートと矛盾**する (回帰は旧・新 2 つ要る)。
2. **dual-time の設計が決まっていない** — BDF2 の差分形、reconcile の呼出順、再開仕様。
3. **RK3 の SST 交換式が無い** — `K_stage − [K_N + b(K_M−K_N)]` と明記し、更新順を固定する。
4. **#0 の「5 % 以内」が結論を先取り** — 分岐ゲートにする。`case/26` の断熱壁は
   `qwall` が**厳密に 0** (200 点すべて) なので熱流束の相対差は使えない。
5. **帰属実験の判定規則が古い** — 「3 倍以上離れる」は成功条件にならない (同程度なら**それが結果**)。

## 踏んだ罠 (繰り返さないため)

- **`rms_dq_*` 列は中身が常に 0** (`main.cpp:450` に明記)。過去 run の遡り調査には使えない。
- **吸収診断の baseline は `res_0.h5` の `ro`**。`res_1.h5` の `roN` は出力直前に
  `updateVariablesOuter` が `roN = ro` で上書きするので使えない (**全 CV で一致する**)。
- **ULP 比で吸収を判定しない**。2 のべき乗境界では下向き ULP が半分 (`Q=1, dq=-4e-8` は比 0.336 だが値は変わる)。
  `check_commit_absorption.py` は float32 で実際に足して判定する。
- **配列が在ることと使われていることは別**。`roK_wf` は `wallTreatmentSST==1 && nodeKwfDirichlet==1` の
  ときしかカーネルに渡らないが、配列はゼロ初期化のまま出力される (「全 CV がピン」と誤読した)。
- **RK3 の係数は float32 格納**。`1/3+2/3` を FP64 昇格すると `1.0000000298` で、
  残差ゼロの定数状態が 100 step で 25 ULP ずれる。
- **`case/49` の本番 run は全部 3D** (106 万節点、AWS `~/forge49`)。CHT の `fem2d` は平面 2D 限定なので載らない。
- **翼列は周期境界**を使うので v1a が ON を拒否する。**翼 CHT の ON/OFF 判別は #4 (周期) 待ち**。
