結論: **補強した案 A を採用し、#3 の最初の変更を「GPU 不要の同一 resolver と、実際に保存量を生成した処理によるハッシュ付与・全入口照合」に絞る。**

付与責任は次のように固定する。

- **新規初期場**：IC 生成処理が解決済み物性を使って保存量を生成し、成功時に付与する。既存場への後付け認証はしない。
- **ソルバ保存場**：ソルバが実際に使用した resolver の結果を付与する。
- **コピー・restart・補間**：SRC の記録を検証し、宛先との互換性確認後に継承する。種変換は、入力の検証と明示的な変換が成功した後に、変換先のハッシュを付与する。
- **属性・対応記録が無い場**：既定で拒否する。例外はその呼び出しだけの明示許可とし、生成 config に恒常的な許可を埋め込まない。不一致の無視とは分け、未検証入力だった履歴を残す。

ハッシュ対象は、種の順序・canonical ID・相・MW・絶対基準の全係数と温度区間・外挿規約・LJ・lump の正規化済み構成と構成実種物性・`thermoHrefTemp` と datum 適用規約・スキーマ版とする。`source`、ファイルパス、配布 DB 全体の版・ハッシュは来歴として記録し、互換性ハッシュから外す。使用していない種や格納場所だけの変更で拒否させない。

CPG は今回の species 照合の対象外とする。液相の追加は #10 まで保留できるが、それまでは **V1(e) 未達であり、凝縮物性全体の互換性は保証しない**。

V1 の成立条件は以下。

| 試験 | 推奨案での判定 |
|---|---|
| A：同一物性 | 場・記録・宛先の照合が成立すれば許可 |
| B：内蔵係数 +0.001／(c)：外部係数変更 | 元の記録との差分で拒否 |
| (a)：保存場だけコピー | 対応記録が無ければ照合不能、宛先物性が違えば拒否。同一物性で正しい記録を参照できれば許可 |
| (b)：記録取り違え | 属性との結合と記録本文のハッシュ再計算で拒否 |
| (d)：起動前の宛先解決 | resolve-only で成立。後回しにしない |
| (e)：液相だけ変更 | #10 完了後に成立。それ以前は未達 |
| 属性・記録無しの旧場 | 既定拒否、その呼び出しの明示許可だけで通す |

これを全入口で試す必要がある。なお、**記録が失われた場合は「どの係数が違うか」は特定不能**なので、V1 の期待エラーは「照合不能」と「係数不一致」を分ける。

第 1 仮説: 問題の中心は、変換器が解決した物性を、別処理が作った保存量の生成物性と同一視していること。 確度: 高  
  根拠: `convertGmshToForge.cpp:28,59,64` と `ic.py:68–85`。特に datum は IC 側の引数で独立に適用される。  
  反証条件: 全 TP 初期場生成経路で、生成に使った物性・datum と resolver の一致が検証され、不一致時には属性付与前に停止する証拠が示されること。  
第 2・第 3 仮説: 無し。

判別 A/B: 宛先 resolver を `thermoHrefTemp=298.15` に固定し、同一 IC 生成処理の **`h_ref_T` だけ** A=298.15、B=0 に変える。CFD は **0 step**、IC 生成から属性付与・読込検証までを試す。見る量は終了状態、属性の有無、記録された datum。**A 許可・B 拒否なら生成者との結合が成立、A/B とも同じハッシュで許可なら、属性は生成物性を保証せず config のラベルになっている。** この試験は提案であり未実行。

やらない方がよいこと: 変換器で先に認証し、Python の上書き後も無条件で残すこと。resolve-only の結果を既存場へ貼るだけで検証済みにすること。欠損属性を宛先ハッシュで補うこと。

呼び出し側の前提への異議: 「IC の熱物性不整合は起動過渡なので別問題」は採らない。`ic.py:68–72` が示すとおり、datum は保存エネルギーの意味そのものを変える。また、保存場のコピー自体は拒否理由ではなく、提供された plan V1 も「(a) の不一致」を拒否条件としている。
