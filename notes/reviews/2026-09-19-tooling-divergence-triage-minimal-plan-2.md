1. **Major — `field` は実装可能ですが、「最初の発生場所」を返す契約にはできません。**

   また、入口∩壁などの所属は重なります。これは実在する問題です。[boundary-node-inlet-corner-wall.md:16](/home/sano/work/forge/plans/active/boundary-node-inlet-corner-wall.md:16)

2. **Major — B1 が必要とする事実が証拠束に足りず、唯一の具体例も node では誤誘導します。**

   **根拠:** v2 §4.2 に、入口・出口の BC 値、IC の流速・圧力・乱流量、`wall_dist` の分布が定義されていません。それでも §5 step 5 は、IC/BC 整合や逆流条件を含む手順書を「1対1で写す」としています。必要な条件は [divergence-and-startup.md:10](/home/sano/work/forge/procedures/divergence-and-startup.md:10) にあります。

   特に §4.3 の `mesh.wall_dist_min == 0` は不適切です。正常な node 壁では壁ノード自身の距離がゼロになります。既存実装も「壁面 CV はゼロでも、最大値が正なら正常な壁距離場」と区別しています。[variables.hpp:59](/home/sano/work/forge/solver_density_cuda/variables.hpp:59)、[variables.cpp:707](/home/sano/work/forge/solver_density_cuda/variables.cpp:707)

   そのため「正常な壁距離＋別原因の初手発散」を壁距離生成へ誘導できます。逆に、入力の全ゼロ距離は読み込み時に `1e30` へ置換されるため、結果場の最小値だけでは入力の欠陥を検出できません。

   `ic.source` にある `inletProfile` も分類違いです。これは入口境界への分布指定であり、uniform IC や restart と併用できます。[boundaryCond.cpp:225](/home/sano/work/forge/solver_density_cuda/boundaryCond.cpp:225)

   **対案:** 最初に採用する規則を少数選び、規則ごとに必要な入力事実を定義してください。IC の生成方法と入口プロファイルは別項目にする。壁距離は入力ファイルの全ゼロ判定・非壁 DOF の非正値・実行時補正ログを区別します。「おおむね一致」「難しい条件」のような文章は、条件・許容値を決めずに規則へ移せません。

4. **Major — §4.4 は「残余ギャップ」を正しく測定できません。**

   **根拠:** v2 §4.3・§4.4。

   - 原因仮説が既知でも、確認作業に長時間かかれば負担は残ります。
   - 原因不明でも、適切な確認を一つ示せれば支援として有用です。
   - `checks` が空でも、正常・対象外なら失敗ではありません。
   - 切り分け run の総数は、不要な run の数ではありません。
   - 最上位の確認で疑いが否定されたことは、誤誘導とは限りません。情報価値のある陰性結果もあります。

   既存 checker にも「収束途中」と「停滞」の区別があるため、発散以外を含む母集団では対象外の扱いが必要です。[check_convergence.py:233](/home/sano/work/forge/solver_density_cuda/tools/check_convergence.py:233)

   現定義では、根拠の薄い仮説と汎用チェックを常に一つ出すだけで「規則未決率」を下げられます。これは目的に逆行します。

   **対案:** 「規則が何かを出した率」と「調査負担が減ったか」を別指標にしてください。独立した採点基準で、次の確認の有用性・危険な提案・追加証拠の必要性を評価する。時間は実作業時間と計算待ちを分け、未解決・打ち切りも残す。run は総数と費用を記録し、「不要」は事前基準に沿う別判定にしてください。

6. **Major — §6.4 は「条件を AND で並べた」だけで、まだ実行可能な単一決定規則ではありません。**

   **根拠:** v2 §6.4。

   主な未定義事項は次のとおりです。

   - 「規則未決率が有意にある」の閾値・分母・測定期間。
   - 「対 B1 の改善」が何の改善か。
   - 「既存エージェント込みの代替に勝つ」の指標と許容差。
   - 許容誤答率を、採用条件としてどう検定するか。
   - 改善の最小実用幅、必要な検出力、評価を打ち切る条件。
   - confidence による棄権と、その後の代替経路を含む総費用。

   95% 区間の下限がゼロを超えても、保守費を回収できない微小改善は通ります。「時間**または**run 数」の選択も、事後的に都合のよい指標を採る余地があります。

   さらに、定義された実験は**開発用30件・非表示の shadow spike**だけです。それでは人間の調査時間や誤変更の削減を測れません。将来側の最終評価へ進む工程・予算もありません。「それ以外は不採用」だと、効果がない場合と単に未評価の場合を混同します。

   入出力にも穴があります。`checks` が空の未決例では、質問する候補 X を誰が生成するのでしょうか。「X を最優先にすべきか」は、代替候補・確認費用・情報価値を含む比較判断です。真偽型にしただけで原子的にはなりません。また、日本語文書の意味解釈が不足の中心なら、数値中心の束を英語化しただけでは必要情報が増えません。

   **対案:** 現計画では「spike に進むか」だけを決め、採用評価は別計画にしてください。そこでは候補集合・入力・英訳・合成規則を固定し、主指標を一つ事前指定する。最小実用改善幅と誤誘導上限を置き、shadow の後に、代替経路込みの比較試験を設けます。効果未確認は「保留／実装しない」と扱い、不効果の実証と区別してください。

## 4. 設計方針

### 4.1 順序の原則

**証拠 → 規則 → 残余の測定 → (必要なら) モデル**。v1 は最後から着手していた。
証拠束 (§4.2) は Jev を使う場合の state builder そのものなので、Jev を採らなくても無駄にならない。

### 4.2 診断エビデンス束 (`diagnose_run.py`)

自由文ではなく**根拠付きの型付き事実**を正本にする。数値は Python 側で処理するが、**監査用に数値・単位・出典を捨てない**。
各項目は `value` / `evidence` (ファイル:行 or 列名) / `status` (`observed` / `unknown` / `not_applicable`) を持つ。

| ブロック | 内容 |
| --- | --- |
| `identity` | case の匿名 ID、離散化 (node/cell)、次元 (2D 平面 / 疑似 2D / 軸対称 / 3D)、commit / バイナリ、メッシュ h5 のハッシュと**変換時の設定** (`discretization`, `nodeInletCornerWall` 等) |
| `settings` | 実効設定と**既定との差分**のみ (スキーム・次数・リミッタ・陰解法・`cfl`/`cfl_pseudo`/`implicitRelax`・乱流・ガスモデル・`pRef`/`roRef`/`uRef`・床値) |
| `ic` | 出自: uniform / 同一メッシュ index コピー / cross-mesh `interp_field` / `inletProfile`。元 run とそのハッシュ |
| `residual` | 全列のトレンドと**最初に非有限になった step と列**。`outer_end` で他 phase を落とさずに走査する。観測 phase・出力間隔・欠測を明記 |
| `field` | 最初の非有限値の**領域** (入口 / 出口 / 壁 / 軸 / 周期 seam / 内部) と座標。`res_*.h5` の最初の異常スナップショットから取る |
| `mesh` | `check_mesh_quality.py` の VERDICT と最悪 AR/skew、**その位置の分類** (壁/軸/seam/内部)。node は primal 計測である旨を明記 |
| `checkers` | 呼んだ checker の版・引数 (`--drop` `--tail` `--from-floor` 等) と生 VERDICT |

`field` の領域分類は既存ツールに無いので本計画で作る (発散診断の中心がここであるため。
`procedures/divergence-and-startup.md` §「最初の非有限値の位置」)。

### 4.3 規則トリアージ (B1) の出力形式

**原因を 1 つ当てる形にしない**。codex 指摘のとおり、原因・症状・場所は別物で、正解ラベルが一意にならない
(例: EOS 床 NaN は反復不安定の終端症状であり、`cfl_too_high` と `eos_floor_washout` の両方に入りうる)。
出力は 3 層に分ける。

1. `observations`: §4.2 の束から機械的に導ける事実。
2. `checks`: **次に確認すべき項目**の優先順リスト。各項目は `procedures/divergence-and-startup.md` の該当節・
   過去 plan・memory へのリンクを必ず持つ。
3. `hypotheses`: 原因仮説。**複数可・`unknown` 可・`insufficient_evidence` 可**。確定ではないと明示する。

規則は弱い文字列検索にせず、§4.2 の型付き事実と既存 checker の結果に対する条件式で書く
(例: `ic.source == uniform` かつ `residual.first_nonfinite_step <= 1` かつ `settings.turbulence == SST` かつ
`mesh.wall_dist_min == 0` → `checks: [wall_dist の生成に no-slip 壁 bcond を使ったか]`)。
**「uniform IC + step 0/1 NaN → IC/BC 不整合」は粗すぎる** (`wall_dist=0` でも初手発散する) ので単独では出さない。

### 4.4 残余ギャップの測定 (これが本計画の主成果)

B1 を回した後に残る負担を測る。**分類精度ではなく調査コストを測る**。

| 指標 | 取り方 |
| --- | --- |
| 規則未決率 | `hypotheses` が `unknown` / `insufficient_evidence` のみ、または `checks` が空になった事例の割合 |
| 調査時間 | 未決事例を人間/エージェントが解くまでの実測時間 (最初の 10 事例で計測して見積もりを更新) |
| 無駄 run 数 | 原因特定までに投入した切り分け run の本数 |
| 誤誘導 | B1 の `checks` 最上位が空振りした割合 |

**この 4 指標が「規則で足りている」と示したら、本計画は Jev を採らずに `accepted/` へ送って終わる**
(それが最良の結末でありうる)。

### 4.5 恒久的な非目標 (採否に関わらず守る)

- フック・`run_case.sh`・設計ループに**外部 API の同期呼び出しを入れない**。診断は常に明示実行の CLI。
  (設計ループは評価器がラッパーを同期呼びしており、API 待ち・外部送信が最適化ループに侵入する。
  5 s タイムアウト × リトライは p95 1 s を保証しない。)
- 外部モデルの出力を AGENTS.md の VERDICT の代替にしない。**高信頼でも原因を確定扱いにせず、
  `divergence-and-startup.md` のチェックリストを省略しない**。
- 外部送信は API キーの有無と独立した**明示 opt-in** で制御する (§6.4)。

### 6.3 事例集合の作り方 (Jev 評価に進む場合も同じ規律)

codex 指摘を全面採用する。

- **単位は run ではなく調査エピソード**。同じ根本不具合の CFL 掃引・restart 派生は 1 事例にまとめる (独立性の確保)。
- **ラベルの出自を固定**: 実行時の config・commit/バイナリ・メッシュ・ログの対応を確立する。
  `config-key-pruning` で 3,491 本の config を移送した履歴があり、**現在置かれている config は当時の入力と同一とは限らない**。
  復元できない事例は「不確実」として区別する。
- **訂正後の結論を使う**: 過去に「真因」とされた説が後で覆っている (軸対称の float 精度説 → 幾何不整合)。
  旧結論が本文に残っているので、必ず訂正後の記述を見る。「変更後に回った」だけで因果確定としない。
- **未知・複合原因・情報不足を残す** (全除外すると実運用で重要な場面を評価できなくなる)。
- **モデル/規則の入力は診断時点で得られた情報だけ**に固定する (事後証拠でラベルを確定するのは可)。
- **分割**: 開発用 / しきい値較正用 / 最終評価用を分離し、**最終評価は将来側の期間**から取る。
  criteria・規則・しきい値の調整に最終評価事例を使わない。
- 母集団の偏りを明記する: 保存済み VERDICT 1,679 件の見出し集計は DIVERGED 167 / NOT CONVERGED 1,448 / PASS 60 /
  分類不能 4 (再判定ではなく保存値の集計)。`NOT CONVERGED` には「まだ収束途中」が含まれる。
  また現行方針は node 主体なので、歴史的な cell 事例の比率は将来の利用比率ではない。

### 6.4 Jev の判断ゲート (前提条件 → spike → 採否)

**前提条件 (すべて満たすまで Jev に着手しない)**

1. §4.4 の残余ギャップが実在する: 規則未決率が有意にあり、そこに**測定された**調査時間が乗っている。
2. その未決事例が「意味解釈が要る」種類である (数値・条件で決まるなら規則を足す方が安い)。
3. 外部送信の**明示 opt-in** が設計されている: 送信項目の許可リスト、case 名・自由文・パスの除去、
   認証ヘッダをログに残さない、キャッシュの権限・保持・削除、**提供者側の保存/学習利用条件の確認**。
4. **固定モデル版**が指定できる (`jev-latest` は可変タグ)。できなければ「保存応答の replay のみ再現可能」と明記し、
   再現性要件を満たさない用途には使わない。
