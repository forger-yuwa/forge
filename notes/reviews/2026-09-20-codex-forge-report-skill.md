1. **【重大】冒頭の結論が、skill 自身の目的を破っている。**  
   根拠: [SKILL.md:8](/home/sano/work/forge/.claude/skills/forge-report/SKILL.md:8)、同:28–31、100。  
   「根拠が主張より先」としながら「結論・要旨が先にあってよい」としています。冒頭に好結果の数値や表を置けば、結果図の位置だけ守って通過できます。また「最初の図」と「最初の結果図」が混在し、領域図の扱いも曖昧です。現状の文章だけでは機械判定の対象が定まりません。  
   **推奨文面:**  
   > 条件節より前には報告の目的と対象だけを書く。数値結果・比較・収束や一致の主張は条件節の後に置く。HTML では条件節を `section#analysis-conditions`、結果を `section#results` に分け、この順で配置する。条件節を折り畳み・非表示にしない。  
   
   DOM 順序は機械確認できますが、条件の正しさや実際の表示順は別途確認が必要です。

2. **【重大】VERDICT の対象が不明でも、チェックを満たせる。**  
   根拠: [SKILL.md:63](/home/sano/work/forge/.claude/skills/forge-report/SKILL.md:63)–75、101。[AGENTS.md:77](/home/sano/work/forge/AGENTS.md:77)–97、120–125。  
   判定区間・対象量・閾値・参照 run が必須でなく、別区間の `PASS` や一部の量の `STEADY` を報告全体の保証として使えます。未実行・判定不能も表から消せます。  
   **推奨文面:**  
   > 各ゲートについて、対象 run・対象量／壁群・判定区間・実行コマンド（閾値を含む）・出力原文・結論への制約を記載する。未実行／判定不能／対象外も理由付きで残す。判定方法と状態別の報告方法は AGENTS.md の該当節に従う。  
   
   これで段階起動、振動時の平均±振幅、単調時の漸近値を独自に再定義せず参照できます。

4. **【重大】条件表が「実際に解いた条件」を保証していない。**  
   根拠: [SKILL.md:45](/home/sano/work/forge/.claude/skills/forge-report/SKILL.md:45)、53–61、79–80。
