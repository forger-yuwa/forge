結論: **C を推奨する。明示指定がない場合の Euler の ni は NS と同じまま維持し、呼び出し側が plan の目的・V2・完了条件を修正したうえで、全生成経路の実効節点数ガードと事前提示を先に実装する。**

第 1 仮説: **V1b の流量比較は、時間変動と単一時刻の抽出に制限されており、ni 900 の採用可否を分離できていない。** 確度: 高  
  根拠: `case/70.m5_air_wt_demo/` 配下の保存済み判定を確認した。

| run | `CONVERGENCE_VERDICT.txt:2` | `quasisteady_series.txt:3–4` |
|---|---|---|
| `run_0015_euler_c2b_ni1800` | `NOT CONVERGED (stalled/plateau)` | M: `STEADY`、流量: `OSCILLATING`、振幅 1.4 |
| `run_0016_euler_c2b_ni900` | `NOT CONVERGED (still converging)` | M: `STEADY`、流量: `OSCILLATING`、振幅 0.29 |
| `run_0017_euler_c2b_ni600` | `NOT CONVERGED (stalled/plateau)` | M: `STEADY`、流量: `OSCILLATING`、振幅 0.37 |

  JSON の ni 900 の流量比差は −9.861043934e−5。許容値 1e−4 までの余裕は **1.39e−6** にすぎない。参照 run の流量振幅は相対約 1.33e−4 で、この余裕を大幅に上回る。  
  反証条件: **同じ定義の流量比**を複数時刻から抽出し、時間変動を含めた差の範囲が許容境界の片側に収まること。現在の差が維持されるなら、合格には両 run の変動を合わせても約 1.39e−6 未満の余裕しかない。

第 2 仮説: 出口 M の ni 依存には空間離散化誤差が寄与している。確度: 中。提示差 +1.53e−4、+3.79e−4 は整合的だが、**2 次の漸近域にあることと、ni 1800 の絶対誤差が約 5e−5 であることは未確認**。

判別 A/B: **変えるのは本段の反復数だけ**とし、ni 1800・900 の組について A＝既存 48,000 step、B＝それぞれ複製した新規 run で同一メッシュ restart から合計 72,000 step まで延長する。NS 入力は固定し、B の追加区間を二つの 12,000 step 窓に分け、同じ抽出による流量比・δ_E・出口 M を既存の `check_quasisteady --series-csv` で判定する。残差は同一設定区間で `check_convergence` を再判定する。

  → **B で両窓とも `STEADY` になり、窓間差・窓内変動を含めても比較差が許容内なら**、「時間変動で判別できない」はこの条件内で解消する。ただし残差が未収束なら、条件付き感度評価にとどめる。  
  → **B でも `OSCILLATING` または許容境界をまたぐなら**、「24,000 step の延長で判定可能になる」を棄却し、V1b は判定不能のまま閉じる。閾値を緩めたり、合格する窓を探して延長を繰り返したりしない。

やらない方がよいこと:

- **A の比規則を採用すること。** 「比 2 だけ合格」という事前分岐の条件は満たしていない。
- **B の Δx_max ≤ 0.047 r_t を汎用の精度基準にすること。** 最大間隔だけでは局所形状・解の勾配・径方向誤差を拘束できない。さらに `min(ni_NS, 必要 ni)` は、必要 ni が NS を超える場合に自分の解像度条件を破る。
- **流量を判定から外すこと。** 結果を見てから受入れ条件を減らす変更になる。

呼び出し側の前提への異議:

- **Major:** 「ni 900 は δ_E・M 合格」は分ける必要がある。M の `STEADY` は確認できたが、δ_E は単一時刻の差が閾値内というだけで、M2 の時間変動ゲートを満たしていない。**δ_E の合格は保留する。**
- **Major:** Richardson 推定値を B の根拠にするのは早い。未収束・振動する流量の平均差を、格子誤差だけとみなせない。**推定値は仮説として残し、既定値の根拠には使わない。**
- case/45 の −0.0008 は、`procedures/nozzle-design-workflow.md:153–161` にある径方向配点・全温未整定・Euler/NS の違いも伴う経緯であり、**ni 単独の証拠ではない**。一方、較正値が設計に入ることは `runner_axismach.py:373–377` で確認でき、既定変更に慎重である理由にはなる。
