# 諮問ブリーフ: 入口の配管の半径を半分にした形 (H) で 370 K の設計へ進む方針 (2026-10-14)

- 依頼者: 主セッション (エスカレーション条件 1: plan の §4 設計方針・§6 検証計画を新規に書く)
- plan: `plans/active/tooling-nozzle-isothermal-wall-chain.md` §4.9 (起案、諮問の前、commit 81a15927)・§5.1 #32〜#36・§8-1 (ユーザ決定)・§6 V-tw370 の結果 (訂正後に結果 B)
- 関連: core-grid plan (feature/nozzle-core-grid) §4.98〜§4.102 (forge-25 → forge-8f の H の A/B と継続、codex の結論「入口マッハ数の下限は今回設けず、今の形を保つ x_respace の組み込み・受入れの確認を優先」)

## ユーザの決定 (2026-10-14)

- 「下限は設けず、単に半分にしようか。」→ 入口のマッハ数の下限の決まりは作らず、**入口の配管の半径を半分にした形 H を M6 の設計に使う** (codex の推奨「今の形を保つ」とは違う、ユーザの判断)。
- 370 K の δ* ループは「G0c・B0 で進める」(上限 1 の参照と比べるのをやめ、設計の量の自己の落ち着きと停止規則で止める案)。この選択は、H を使うと決める前の質問 (今の形を前提にした選択肢) への答え。

## 観測事実

- H (core-grid plan §4.98・§4.99・§4.101): 配管 r 3.2425 r_t (x ∈ [−12.5, −9])、縮流部 (−9, 3.2425, 0, 0) → x = 0 の今の物理の壁の (r 1.0013889, r′ 7.743e−4, r″ 0.501183) の 5 次 Hermite、x ≥ 0 は今の物理の壁。格子は Gref (ni 4719・nj 160) の x の station のまま、第一層の比を r_今/r_新 倍して実寸を保った (AR 最大 4573)。B0 (上限 50) のまま、縮流部 x ∈ [−8, −2] の残差は今の形 C の 1/48〜1/170 (継続の 4 万 step でも保つ)、θ_r[65,75]・Q_w は STEADY、全域の残差は 8.6e−8 で横ばい (C の停滞 2.0e−5 の約 1/230)。改善の主因がマッハ数か格子の形・境界層の履歴かは分けられていない。形を変えない Grefc (縮流部の x を粗くした格子) でも停滞は大きく改善した。
- 今の形での G0c (`x_respace`、縮流部 x −8〜−2 の流れ方向の密度を半分) は、300 K で登録の Q32 の起点 (§6.58・§6.61) とチェーンの開始の手順 (V-g0c-chain) から B0 で T2 との比較の要件を満たした。370 K (V-tw370) は、上限 1 の参照 (G0・G0c) が 20 万 step で停止規則に届かず、訂正後に結果 B。記録の値では、試験部の δ_target の上限 50 と上限 1 の差は 0.003〜0.011 mm、スロートの近くの δ_target の末尾 2 万 step の振れは 0.27〜0.66 mm。
- チェーンの問題 YAML の上流の形: `geometry.r_inlet` (今 6.485 = 0.5 m / r_t)・`L_U` (今 12.0)・`L_pipe` (今 0.5)・`pw_upstream: poly` (配管〜設計スロートの 5 次多項式)。forge-25 は今の物理の壁の x ∈ [−12, 0] が (−12, 6.485, 0, 0) → x = 0 の壁の値の 5 次 Hermite と 5e−15 で一致することを確かめた。H は `r_inlet 3.2425`・`L_U 9.0`・`L_pipe 3.5` にあたるはず (μ = L_U²/(RΔr) = 18.1 ≤ 20)。
- 冷却壁の格子の表 (`wall_first_frac_table`) は局所半径との比、`x_density_table` は x の相対密度。
- 停止規則: こちらの §6.11 の `m9_watch.py` はチェーン経由で終了分類を取り違える欠陥がある (V-tw370)。forge-f5 が設計チェーンに入れた `stop_rule.py` (feature/nozzle-cooled-wall-settling 66364fff) は forge を子プロセスとして持ったまま見張るのでこの欠陥が無いが、判定の量 (入口−出口の質量の収支、θ_r の平均の変化・振幅) が違う。case/70 (入口の直管 M 約 0.03) では質量の過渡で未到達。
- main に設計チェーンの修正 3 つ (帯局所の抽出・単調性の検査・出口の終点 +5.35 mm) が入っている (PR #7)。

## 方針の案 (plan §4.9)

1. H を問題 YAML (`r_inlet 3.2425`・`L_U 9.0`・`L_pipe 3.5`) で表し、forge-25 の H の壁と一致、x ≥ 0 は今と同じ、を確かめる。
2. 第一層の表を r_今/r_新 倍して実寸を保つ。x の station は今のまま。品質を確かめる。
3. H で G0c を使うか、G0 (細かい格子) と B0 で足りるか。
4. 370 K の δ* ループの止め方: 各 pass の本段は停止規則で、pass の間の δ_target の変化が試験部で絶対の許容 (案 0.05 mm) 以内で止める。スロートの近くの振れの扱い。
5. 前提: main の 3 修正の取り込み、見張りの欠陥の修正 (stop_rule.py の取り込みか m9_watch の修正)。

## 問い

1. 方針 1〜5 の妥当性と順序。特に、ユーザの「G0c・B0 で進める」は H の決定の前の答えなので、H では G0c を使うべきか、G0 + B0 にするか (速さ・精度・これまでの G0c の検証の流用の可否)。どちらでも、H で何を確かめれば足りるか (上限 1 の参照は 370 K で止まらなかった)。
2. 370 K の δ* ループの止め方 (停止規則の選択、δ_target の絶対の許容の値と場所、スロートの近くの扱い)。「上限 1 の参照と比べない」ことで失うものと、その補い方。
3. H の形をチェーンに入れる前に要る確認 (壁の一致、格子、品質、出口の終点の修正との順序)。
4. ユーザの決定 (下限を設けず H を使う) と、core-grid の codex の推奨 (今の形を保つ) の違いを、plan にどう書くか。
