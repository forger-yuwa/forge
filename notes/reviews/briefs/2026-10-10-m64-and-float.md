### 1.3 float のビルド (§6.21)

- 既定化した FP64 (`typedef double` の flow・geom) は 32.0 ms/step。既定化した float は 20.5 ms/step (同じ B0 の構成・同じ出発点・1000 step × 3 本・専有)。
- Thomas は両方とも内部が double (§6.12 の内訳で 12.6 ms/step = 分解 4.58 + 代入 1.60 × 5)。
- float で 1000 step 後の残差は FP64 の約 10 倍 (`rms_ro` 9.5e-5、`rms_roUx` 1.2e-2)。発散はしていない。
- 冷却壁の第一層 (記録 [cooled-wall-mesh-precision]、2026-10-08):
  - `geom_float = float` だと座標・体積・面ベクトルが float32。第一層厚 / 局所半径 = f のとき第一層は約 f / 1.2e-7 ulp。f = 3.4e-7 で 3.6 ulp、第一層厚が最大 28 % ずれた。
  - case/45 の第一層は 0.06〜12 µm、半径は 0.1〜0.8 m。
  - FP64 は `flowFormat.hpp` の typedef 4 行 + `gmshReader` の `stod` (c096d66c)。19.4 万節点では FP64 が FP32 の約 2 倍遅かった (3.4 → 6.9 ms/step)。
- `flowFormat.hpp` は `flow_float`・`geom_float` (と `*3`) を別の typedef で持つ。
- 定常の float の commit は、|dq| < ½ ULP(Q) で丸めに消える (`methods/time_integration/implementation.md` の「commit の丸め」)。`time.deltaT.qAccumulatorFP64: 1` は軸対称では使えない。

## 5. 呼び出し側の仮説 (検証していない)

- **H1**: M64 は、残差の床が住む領域 (軸から j 20〜56) を point に戻した。そのため、その領域の止まり方が point と同じになり、床の大きさ (ω 以外) も point と同じになった。θ_r が R に近づいたのも同じ理由。
  - そうなら R3 のフラグは「point の側へ寄った」ことの表れで、悪化ではない。
  - ω の床が B0 より高いのは、point の ω の床 (3.58e3) がもともと高いことの名残。
- **H2**: M64 の到達が B0 より 12 % 多くの step を要したのは、point に戻した領域の Δτ が point と同じになり、そこでの過渡の抜けが遅いため。
- **H3**: 状態を float にしても、Thomas (12.6 ms、double) は変わらない。残り (FP64 で約 19.4 ms) が float で約 7.9 ms になったと見られ、混成ビルドでも幾何との積で倍精度に昇格する分だけ戻る。
