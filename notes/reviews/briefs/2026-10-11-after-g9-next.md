## 1. 観測事実 (§6.40〜§6.43、AWS A、各 2,000 step、x/r_t < −2 の内点 83,310 節点、参照の型への射影 a は既存の float − FP64 の平均の応答が 1)
| 腕 | a (3 本) | step 2,000 の温度の FP64 (C) との差: RMS / 最大 / 1 K 超の節点 |
| --- | --- | --- |
| C: FP64 ×3 | 0.2164〜0.2166 | 0.002〜0.003 K / 0.05〜0.08 K / 0 % |
| E: FP64 + ρE だけ step 末尾に float32 に量子化 ×3 | 0.218〜0.225 (e_E +0.006 [−0.007, +0.018]) | 0.16〜0.19 K / 4.4〜5.5 K / 0.6 % |
| G9: FP64 + 9 保存量すべてを量子化 ×3 | 0.201〜0.206 (e_G9 −0.013 [−0.024, −0.001]) | 0.28〜0.31 K / 5.4〜6.5 K / 1.2〜1.3 % |
| F: float ×3 | 1.04〜1.23 (e_F +0.91 [+0.57, +1.25]) | 3.7〜4.5 K / 119〜134 K / 5.4〜5.7 % |
- 判定はどちらも結果 B (末尾の量子化だけでは登録した成分は出ない)。量子化の自己点検は合格 (G9 の化学種の履歴は入口のピン 121 節点と ghost だけ表せない値、事前に許した形)。
- 入口〜収縮部の静圧: 入口 5.4989e6〜5.4995e6 Pa、収縮部 5.317e6〜5.4995e6 Pa。float の 5.5e6 の刻みは 0.5 Pa。
- float のビルドで float32 に格納する原始量・物性: P・T・Ux・Uy・Uz・Ht・sonic・γ・粘性係数・熱伝導率・vis_turb・Y・勾配・リミタ係数など (FP64 のビルドでは double)。G9 では状態を丸めても、そこから作る原始量・物性・勾配・流束・残差は double。
- `space.pRef` (既定 0): SLAU の内部の面・境界の半割面・hoop ソースで圧力の項を (p̃ − pRef) で組む。p − pRef は入口で約 −100〜500 Pa、収縮部全体で約 −182,000〜500 Pa、出口で約 −5.5e6 Pa (codex の前回の指摘)。

## 2. 呼び出し側の案 (未検証)
- **案 A (pRef の試験、コード変更なし)**: Cp = FP64 + `space.pRef: 5.499e6` ×3、Fp = float + 同じ pRef ×3 (run 番号 `run_0700〜0705` を確保済み)。比較は Fp 対 Cp。前提として Cp と C の同等性 (FP64 で pRef が作用素を実質変えないこと) を事前の許容幅で確かめる (例: a の差と温度差の RMS が C の再実行の差の何倍以内か)。判定は区間全体で: 「抑制」= e_Fp の区間 ⊂ [−0.5, +0.5] かつ e_F から有意に小さい、など。解釈は「この圧力ゲージの変更で登録成分が減った」まで。
- **案 B (原始量の量子化の試験、診断のコード変更が要る)**: FP64 のビルドで、EOS・物性の後 (`assembleResidualPre` の `gasProperties` の後) に、原始量と物性 (P・T・Ux・Uy・Uz・Ht・sonic・γ・μ・λ・vis_turb・Y) を float32 に丸める診断を足す (§5.1 #19 の量子化の診断に「原始量の段」を足す形)。腕 Gp = FP64 + 原始量の量子化 ×3 (+ 9 保存量の量子化も同時にした Gp9 ×3)。G9 対 Gp で「原始量・物性の格納の精度」が要るかが分かる。陰性なら残るのは流束・勾配・リミタ・粘性・ソースの演算の中の丸め。
- 呼び出し側の好み: 案 A を先 (速い、効けば設定 1 行の対策)。案 B は A の結果を見て。
