# 諮問ブリーフ: §6.35 (平均流を FP64 で積む float の軌跡) が判別不能 — 解釈と次の一手 (2026-10-11)

- 依頼者: 主セッション (AGENTS.md のエスカレーション条件 3: 事前登録の比較が判別不能、7: result の解釈を確定する前、1: 次の §6 を足す)
- plan: `plans/active/architecture-float-state-double-geometry.md` (§6.26〜§6.35、§5.1 #15・#18)

## 0. 問い
1. §6.35 の記録 (平均流の 5 保存量を FP64 で積んでも float は B とほぼ同じに離れた) から、plan に書いてよい範囲はどこまでか。
2. §6.33 と §6.35 はどちらも、結果 R (抑制不十分) の「効果の大きさ」の条件は満たしたのに「|m − ΔA| > 10 N」で外れた。次の試験の判定の式をどう組むべきか (結果を見る前に決める)。
3. 次の一手として下の §3 の案 (FP64 のビルドで、commit のたびに状態を float32 に丸めて戻す) は妥当か。ほかに優先すべき切り分けはあるか。

## 1. 観測事実
- §6.27 (確定): 共通の Q32 の起点 (`_tr/q32_init.h5`) から 30,000 step。FP64 の A (`run_0487`) は θ_r が ≤ 0.12 % しか動かず、float の B・B′ (`run_0488`・`0489`) は +0.9〜1.9 % 動く。D = (+1.892, +1.647, +1.431) %。
- §6.29: SST の輸送の更新を止めても float は離れる (判別不能)。
- §6.33: block の系の組み立てを double にした C・C′ も B と同じに離れた (mB の 94〜97 %、判別不能)。
- §6.35 (今回、AWS A、`run_0592`〜`0594`): 平均流の 5 保存量を FP64 の正本で積んだ E・E′ も B と同じに離れた。A からの離れの平均は mB の 98〜104 % (θ_r)。前提はすべて合格 (単体試験、SASS 282/283 一致で違うのは `enforceAxisSymmetry_d` だけ、res_0 の 9 保存量のビット一致、採用の mask は等温壁の ρE だけ、同じバイナリの OFF の対照 F は B・B′ の範囲)。判定は判別不能 (S 0/6、R 0/6。R は 6 組とも「A から 0.5|D| 以上」が成立し「|mE − ΔA| > 10 N_E」で外れた。N_E = 0.20〜0.47、B と B′ の差 0.07〜0.14 より大きい)。表は plan §6.35。
- §6.26 の腕の commit の診断 (登録外の記録、§6.34): float の B は 500 step ごとの各時点で、内点 561,323 節点のうち要求した更新が丸ごと消えた節点が ρ 5.4〜8.2 万、ρu 2.4〜3.9 万、ρE 3.1〜4.7 万、k・ω・ρY も数千〜数万。FP64 の A は 0。更新量の合計に対する実際の比は float でも 0.9999。
- E・E′ でも k・ω・ρY は float のまま (qAccumulatorFP64 は平均流の 5 本だけ)。E・E′ の commit の診断はρ..ρE を計らない。

## 2. 呼び出し側の読み (未検証)
- 「平均流の状態の commit の丸め・吸収は、少なくとも単独では登録の窓の偏りの通り道ではない」と読みたい。ただし codex の前回の指摘どおり、k・ω・ρY の状態の丸め、要求の更新の生成 (float の残差・float の d)、EOS の再構成は残る。
- 3 つの介入 (SST の更新を止める・組み立てを double・平均流を FP64 で積む) がどれも効かなかった。

## 3. 次の一手の案 (呼び出し側の案、未検証)
- **逆向きの試験**: FP64 のビルドで、step の末尾 (reconcile と Q_N = Q の直前) に**状態の 9 保存量 (ρ..ρE・ρk・ρω・ρY) を float32 に丸めて double に戻す**診断の切り替えを足す (環境変数、カーネル 1 本)。これで「状態の保存の精度」だけを float にした FP64 のビルドができる (残差・勾配・流束・EOS・線形の解きは double のまま)。
  - G = FP64 + 状態の丸め、G′ = G の再実行。A (FP64) と B・B′ (float) と比べる。
  - G が B の方へ離れれば「状態の保存の丸め (k・ω・ρY を含む) が通り道に要る」、A のままなら「float の演算 (残差の評価・要求の更新の生成) の側」。
  - 平均流だけを丸める腕 (H) と、k・ω・ρY だけを丸める腕 (I) に分けると、§6.35 との整合と k・ω・ρY の寄与が見える (計 4〜6 本、B か A で各 30,000 step・約 1 時間)。
- 判定の式: §6.33・§6.35 で R が「10 N」で外れたので、再実行の差の見積もりを腕ごとの 2 本の差でなく、同じ精度の腕を全部プールした差 (float は B・B′・C・C′・E・E′・F の 7 本、FP64 は A の 1 本だけ) で取る案。倍率を下げる根拠にしないこと。
