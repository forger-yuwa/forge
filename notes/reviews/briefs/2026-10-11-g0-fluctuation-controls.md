## 0. 問い

1. 下の観測は、キー 1 (区間ごとの r 重み)・新しい格子 (境界の半割面の端点を丸めた中点にそろえた変換器)・ビルドの差 (段 ④ fgeom5 → hoop の修正 fgeom7) のどれが揺れを増やしたかを分ける必要がある、という理解でよいか。
2. 切り分けの最小の組み方は §3 の 2 本 (G0 で FP64) でよいか。腕・出発点・長さ・揺れの物差し・判定の閾値として何を事前登録すべきか。
3. float plan §6.20 (float と FP64 の停止規則での比較、FP64 の腕 `run_0483` が未到達) の判定は、この揺れのもとで成り立つか。待つべきか、扱いを変えるべきか。

- fgeom5 → fgeom7 のソースの差: fgeom6 (`cb6a0d8b`: 変換器が常に double の幾何を書く・float32 の幾何の警告・restart_field の座標の照合) と fgeom7 (hoop の修正)。ソルバの数値の経路の差はキー 1 の面ベクトル (と `ss`) のはず (未検証)。
- `run_0483` と `run_0482` (キー 0、同じ新格子・同じビルド) は同時に投入したが、`run_0482` はユーザ決定 (比較を新格子 G1 へ移す) で step 9,447 で止めた。G0 の新格子のキー 0 の定常の揺れのデータは無い。
- 起点: どの run も `run_0183` の res_100000 から B0 の実効設定 (cfl 4・ライン陰解法・方向別 Δτ・上限 50・`implicitThermalJacobian 5`・緩和 0.7)。

## 2. 期待値

- 揺れの由来の候補: (a) キー 1 で軸の近くの面ベクトル (W_f と ss) が変わり、ラインの行列や流束の釣り合いが変わった。(b) 境界の半割面の端点の変更が、壁・入口の CV の幾何を変えた (キー 0 にも効く)。(c) ビルドの差 (fgeom6 の変更) にソルバの数値を変えるものが混ざった。

## 3. 呼び出し側の案 (検証していない)

- インスタンス B (空き) で FP64 の 2 本を同時に回す。どちらも `run_0183` の res_100000 から B0 の構成、`run_0483` と同じ停止規則 (上限 20 万 step) か、固定の 14 万 step:
  1. **K0**: 新格子・キー 0・fgeom7 (`run_0482` の組み直し)
  2. **OLD**: 旧格子 (`run_0183` の nozzle.h5)・fgeom7 (rSurfVect が無いのでキーは効かない)
- 並べ方: (OLD 対 `run_0452`) = ビルドの差、(K0 対 OLD) = 格子の差、(`run_0483` 対 K0) = キーの差。物差しは上の RMS (同じ窓: 例えば 10〜14 万 step)。
- 判定の案: 揺れの RMS の比で 2 倍を超える差を「効いた」とする? (閾値は未定。再実行の揺れの物差しが無い)
- 所要: B で 2 本同時なら各 2〜3 時間。
