# 諮問 5 回目: 補間壁 vs 同時当てはめ壁の Euler A/B の組み方 (ノイズ床・判定量・事前登録)

日付 2026-10-05。前回までの記録: plan `plans/active/verification-m6-axis-wave-mesh-su2.md` §5.1 #13 ①〜⑦、§9 (2026-10-05 の各行)。AGENTS.md 条件 1・4 (検証計画を新たに書く / plan に無い run の前)。

## ユーザ判断 (2026-10-05)

- スロート直後の角度オフセット (Hall 初期線と MOC の不整合、a_θ ≈ 0.097°; 整合化で 78 % 減、登録基準 80 % に未達) は「差が出て当然」。
  なくすなら初期線を CFD の遷音速場でピンするが、**探索段階では不要、形状を詰めるときの選択肢**。原因追究はここで区切る。
- 次は「スロート直後の 0.1° が試験部の圧力波・オーバーシュートに効くか」を Euler で測る (AWS 起動承認済み)。
- 評価の観点: 軸 M は形状の生成器。壁がなめらか・試験部に圧力波なし・オーバーシュートが小さい (凝縮を強める)。

## 提案 (当方)

オフセット自体は両腕に入ったまま (どちらも同じ MOC 点群) なので、この A/B は「オフセットの有無」ではなく
**「始点の扱いと下流の毛羽が違う 2 つの壁表現のどちらでもよいか」**を見る。オフセットの有無そのものの Euler 比較は、
整合初期線で設計全体が動く (m* −0.07 %、出口半径 −0.25 mm) ため交絡し、ユーザ判断で今は行わない。

- 共通: problem `case/45.isobutane_m6_d155/problem_d155_ns_c2final.yaml` を `n_axis_inv` 2400 に (壁 609 点)、Euler (slip) の生産レシピ = `runner_axismach.prepare`
  (段階起動・cfl・relax は run_0037/0047 と同じ)、同一バイナリ (main 統合後の AWS ビルド; `RUN_PROVENANCE.txt` の sha256 を記録)、同一メッシュ条件、
  IC は `run_0047_euler_rt77p02_newbin` 最終場から `interp_field` (両腕同じ)。
- A: 補間壁 (`AxisMachCFDWall`、現行)。
- B: 同時当てはめ壁 (`case/45.isobutane_m6_d155/moc_wall_fit_ab.py` の `joint_fit`、λ=1e-9、h₀ 0.0125・h₁ 0.5、始点 r′=0, r″=1/R、出口 r と r′ をハード拘束)。
  形状: MOC 点との差 最大 2.5e-5 r_t (x=0.026)・0.028° (x=0.052) (始点 2 点だけ)、x≥0.08 では 1e-6 級。r″ の局所極値 5 (A は 256)。
- ノイズ床: A を 3 本 (同一入力、再実行差) → 量ごとに max(3 本の最大差 × 3, 絶対下限)。
- 判定量 (r/r_w = 0.1 と r=0、試験部 x ∈ [x_E+2, x_F−1]): 波 (10 r_t P-spline 残差の最大; #12 ② の窓端の敏感さあり)、オーバーシュート (x ≥ x_E−15 の M/M_d−1 の最大)、
  出口コア M (η 0.05〜0.7)、加えて実圧力の指標 (codex 1 回目の指摘: P/P_ref の同様の残差)。量ごとに `check_quasisteady` の VERDICT。
- 判定案: B−A の差が全量でノイズ床以内 → 「壁表現の違い (始点 2 点の 0.03° 級と下流の毛羽) は Euler で区別できない」として、
  始点 2 点の点上ゲートを Euler 根拠で緩める判断材料にする (緩和そのものはユーザ判断)。B が A より悪化 (ノイズ床外) → 当てはめは不採用。
