# 諮問ブリーフ: M_knot の自動選択で、解像度のゲートが選び直した値と出力の関係 (plan tooling-nozzle-mknot-auto §4.2〜§4.4、#3 の前)

AGENTS.md 条件 1 (§4 の方針の穴を埋める)。判断役のスイッチが codex。

## 観測事実 (plan §9 の 2026-10-14 の 2 項目)
- §5.1 #2b を実装 (`design/forge_design/evaluate/mknot_select.py`)。`select_mknot` は N の解像度の境目で選ぶ。`resolution_gate` は N と 2N の境目の保守的な側を共通の境目にし、
  N と 2N をそれぞれ選び直して比べる (選択の差 ≤ 0.01・制約・距離・詰めの端)。選び直した N の値 `chosen_N` と `moved_N` (= chosen_N − select の選択) を返すが、`moved_N` は合否に入れていない。
- M5 の V1a・V6 では共通の境目は N の端のまま (2N の境目は保守的でない側へ −0.000625 / −0.00125) で、`chosen_N` = select の選択 (`moved_N` 0)。
- 合成の試験 (i): 2N の下の境目が保守側へ +0.02 動くと、共通の境目は 2N の端、N・2N とも選び直して 2.070625 (差 0 で合格)、`moved_N` +0.02、select の選択 2.050625 は共通の境目から 0.03 (< ΔM_safe 0.05)。
- §4.3: 最終の (r_t, M_K, geometry) の組で詰めとゲートと制約を確かめ、「選んだ値が 0.01 を超えて動いたら、その値で r_t の固定点をやり直す (最大 2 回)」。§4.4: YAML の `geometry.M_knot` は選んだ数値。

## 実装担当が挙げた穴
1. ゲートで選び直した `chosen_N` が `select_mknot` の選択と違うとき、YAML に書く値はどちらか (§4.3・§4.4 に無い)。select の値をそのまま書くと、共通の境目から ΔM_safe 未満の値が出うる。
2. ok_N/ok_2N を入力の点と選び直した 2 点の全部・両方の解像度で見る (V2(g)「高い解像度だけ制約違反 → 例外」を通すため)。距離は選び直した 2 点だけ。
3. N と 2N の境目を対にする幅は窓の半幅 0.1、片方の解像度にしか無い境目は残す (保守側)。
4. 境目 + ΔM_safe の点は全部の境目 (範囲内) で評価して候補に足す (順序に依存しないため; 評価点が境目 1 つにつき 1 点増える)。

## 問い
