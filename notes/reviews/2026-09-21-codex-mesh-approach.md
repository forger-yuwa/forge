# codex 相談: 3D メッシュの作り方 — 自作メッシャ vs CAD + Salome

- **stage**: 自由質問 (plan/result 段ではない)
- **date**: 2026-09-21
- **judgement**: **(a) 自作メッシャの改修を推奨** (条件つき)
- **プロンプト**: `notes/reviews/2026-09-21-codex-mesh-approach.prompt.md`

## 依頼内容

⑤ SERN 3D メッシュを **(a) 現行の Python 手書き構造化ヘキサメッシャ `mesh_sern3d.py` を直し続ける** か
**(b) 3D CAD を起こして Salome でメッシュを切る** か。推奨を 1 つに絞るよう指定。
材料は本日の到達点 (品質 SOFT-PASS / y⁺ ramp 0.549 / 4 係数とも格子収束許容内 / 3.22M 節点)、
潰した候補 6 件、残る欠陥 (厚さ 0 の交線で ρ が床)、およびその修正設計が受けた **Major 7 件**。
評価指定: Major 7 件の消長、forge 側の入力制約、y⁺≈1 の層生成、無人生成、移行で捨てるもの。

## 結論 (codex 原文の要約)

**(a) を推す。ただし「`dup2` と接続を維持して座標だけ動かす」案は撤回し、有限厚の接合部を明示した
ブロック接続へ直すことを条件とする。** 今回の NO-GO が示すのは**現行の接続を温存した有限厚化の破綻**であって、
自作構造格子の限界ではない。

**Major 7 件は (b) で全部は消えない**:

| 指摘 | (b) で構造的に消える | 形を変えて残る |
| --- | --- | --- |
| 1 露出カウル側端の欠落 | 正しく閉じた固体なら側端は実在する境界面 | 側端形状・流体領域の閉性・壁タグ・壁距離・力への算入 |
| 2 `j=jm` に厚みを与えられない | `dup2` の索引条件という制約は消える | カウル×側壁の接合断面・微小面/隙間・接合角の層生成 |
| 3 別ブロックが旧 `zs[k]` を使用 | 共通 CAD から整合メッシュ化すれば座標更新漏れは消える | CAD を分割するなら接合面の一致・共有節点 |
| 4 `L_sw` が station に無い | CAD で後縁を正確に置けば最近傍丸めは消える | テーパ終端形状・CAD 許容差・dv 変更後の後縁識別 |
| 5 既定でビット一致しない | **消えない** | 旧経路保持か互換要件変更かの判断・回帰検証 |
| 6 入口幅と力の帳簿が不整合 | **消えない** | 実入口面積/流束と係数基準の分離・YAML→評価の変更 |
| 7 新モードの試験不足 | **消えない** | 新形状 + CAD・変換・混合要素・無人生成の試験 |

**(1)(2)(4) を解消するのは「非構造格子だから」ではなく、物理形状と接続を格子索引から独立させること**であり、
それは (a) でも実施できる。厚さ 0 の交差面を残したまま Salome に渡しても内外の接続問題は残る。

**forge の node 中心方式は全壁に双子ノードを要求しない**。双子は厚さ 0 の壁の両側に別状態を持たせる表現であって、
有限厚なら内外を物理的に離せる。ただし残したスリットでは内外の節点 ID を区別し、
変換時に座標一致だけで統合しないことが要る。

**(b) の取り込みは拡張子変換では終わらない**:

- node 経路は `convertGmshToForge` が median-dual を構築している (`convertGmshToForge.cpp:41`)。
  移行するなら **MED/UNV → 境界群を保持した msh4.1 → 既存変換器**を新設・検証するのが妥当。
- **Fluent CFF 経路は node 経路の代用にならない**: Fluent のセル数を引き継ぎ、セル節点の平均を CV 中心にしている
  (`fluent_h5_to_forge.py:442, 498`) = cell 中心。
- 境界群 → `physID` の固定対応、新しい側端面の BC、壁距離への組み込みが要る
  (`boundaryCond.cpp:138`, `calcWallDistance_kdtree.cpp:112`)。
- 受入試験は要素接続順・境界群・単位・節点同一性・**変換後の双対体積と閉性**まで含む。

**境界層**: Salome の Python API にプリズム層生成 (層数・総厚・成長率) はある。ただし無効プリズム回避で
層厚が制限され得るので、**指定した第一層厚を全接合部で維持できる保証とは別**。
また **y⁺≈1 から必要層数は一意に決まらない** (成長率・全厚・外側格子への接続が要る)。
提示値でも `cowl_in` 1.234 / 側壁 188 なので (a) でも全壁の解像は未完了。

**無人化**: Salome は Python API を持つので可能。ただし必要なのは「一形状で生成できる」ことではなく、
**dv を数十〜数百ケース振っても形状生成・境界群識別・層生成・変換が成立すること**で、その成功率は未検証。

**移行費用を決めるのは捨てるコード量より再取得する検証量**。(a) でも有限厚化で形状が変わるので
今日の格子収束は修正後の証明には使えないが、**構造格子の配置則・msh4.1 変換・既存の起動処理を保ち、
変更を接合部と帳簿に絞れる**。(b) はそれに加えパラメトリック CAD・境界群の安定識別・変換経路・
層生成・設計範囲全体の無人試験が必要。**今日の格子収束結果は比較資料としては残るが、新経路の受入証拠にはならない。**

最初にやるべきは、**小規模格子で露出側端・側壁下端・機体接合を閉じ、物理 station を固定し、入口帳簿を整合させること**。
修正だけで密度床が消えるとは未確定。

## 当方の採否

**全面採用。(a) で進める。** 決め手は 3 つ:

1. **(5)(6)(7) は (b) でも消えない**。とくに **(6) 入口幅と力の帳簿** はメッシャと独立で、
   どちらを選んでも同じ作業が要る。「CAD にすれば片付く」は成立しない。
2. **Salome → forge の node 経路が存在しない**。`fluent_h5_to_forge.py` は cell 中心なので代用にならず
   (`:442, :498` を確認)、MED/UNV → msh4.1 → `convertGmshToForge` を新設する必要がある。
   その受入試験 (双対体積・閉性・境界群・節点同一性) は今日の品質ゲート一式と同等の規模。
3. **無人生成の成功率が未検証**。設計チェーンは dv を振って形状が毎回変わるので、
   ここが崩れると MOO が止まる。現行は実績がある。

**ただし「座標だけ動かす」設計 (§4.44) は撤回する**。接合部のトポロジを明示的に設計し直す。
規模が §4.44 の見積もりの 3〜5 倍になるので、**本 plan とは別の plan に切り出す** (R5q を移管)。
本 plan の 3D 受理は「厚さ 0 交線に床張り付き 12 ノード (320 万節点中)、格子細分で悪化」を
**既知の限界として明記**して締める。

**保留**: codex が「修正だけで密度床が消えるとは未確定」と留保している点はそのとおりで、
新 plan の完了条件は「床ノード 0」に置き、達成できなければ再設計する。
