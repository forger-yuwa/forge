結論: **Gref の point だけを同じ設定で追加 8 万 step 継続し、通算 160k〜200k の自己変化で参照資格を判定する新試験を登録する。**

第 1 仮説: Gref の point に残る減衰傾向の変動は、追加 8 万 step によって必須 8 量の資格条件内まで小さくなる。確度: 中  
　根拠: `case/45.isobutane_m6_d155/run_0613_cg_gref_point_ext/` の記録では、通算 80k〜120k の θ_r [65,75] の増分は約 0.036 → 0.015 %、Q_w は約 0.034 → 0.013 %へ減少している。ただし既存 VERDICT は **`NOT CONVERGED (still converging)`、θ_r 2 量は `DRIFTING`、Q_w は `TRANSIENT-UNSETTLED`**（[plan §4.29](/home/sano/work/forge-coregrid/plans/active/tooling-nozzle-core-grid.md:624)）。  
　反証条件: 通算 160k〜200k の必須 8 量のうち、いずれかが下記資格を満たさない。「追加 8 万で解消する」を退ける。

第 2・第 3 仮説: 追加しない。B0 の停滞原因や両格子の最終的な差は、この継続試験だけでは特定しない。

判別 A/B: **変えるのは継続長だけ。** `run_0613` の `res_60000.h5` から `restart_field.py` で新しい run に再開し、9 保存量のビット一致を確認する。point・CFL・緩和・格子・境界条件・バイナリは固定する。Grefx は再実行しない。

- 追加 80,000 step、2500 step ごとに保存。最後の 40,000 step、すなわち point 通算 **160k〜200k の17出力**を評価する。
- μ_ref,point は 180k〜200k の時間窓平均。d は 160k〜180k の平均との差、U は 160k〜200k の各値から μ_ref,point までの最大差。
- 必須 8 量すべてで、非有限 0、`check_quasisteady --tail 1.0` が **STEADY**、d ≤ τ/8、U ≤ τ/4、漸近値と最終値の差 ≤ τ/8。閾値の換算は §4.26 と同じ。単調な量は漸近値も報告する。
- 残差は同一設定の point 通算 0〜200k で全保存量を判定する。B0 区間を連結しない。`NOT CONVERGED` ならそのまま明記し、量の資格通過を「残差も収束した」と読み替えない。

→ **A: 全量が資格を満たす**なら、「この評価窓でも資格不足が続く」を退け、新基準による比較へ進む。  
→ **B: 一量でも満たさない**なら、第 1 仮説を退け、参照資格なし・判定不能で停止する。これは継続長の検査であり、B0 の原因を判別する A/B ではない。

新しい比較式は、次で固定する。

`E′ = μ_x,base − μ_ref,point`

`B′ = |E′| + U_x,base + U_ref,point + p_x + p_ref + s_x + U_x,point ≤ τ`

相対量は各項を共通の **D = |μ_ref,base|** で百分率に換算し、分母は従来値を維持する。基準の値を替えることと、百分率の尺度を替えることを同時に行わない。出口の主流 M は相対 %、軸・η 0.1 の M は %pt とする。

Grefx の B0・point の評価窓、p、τ、必須 8 量は固定する。`s_ref` と `U_ref,base` は新予算から外し、旧基準との差として記録する。全量で資格と B′ を満たしても、結論は**指定した参照・許容差に対する精度面の候補**までで、真値への誤差保証や Gref の方式非依存性ではない。総時間の条件も別に残る。

等比 0.88 が続くという仮定で計算すると、θ_r の 180k〜200k の端点差は約 **0.0095 %**、前後 2 万 step の窓平均差 d は約 **0.0124 %**。Q_w はそれぞれ約 **0.0082 %、0.0108 %**となる。8 万 step という予算には根拠があるが、外挿は資格判定の代用にしない。40 ms/step なら計算本体は約53分。

やらない方がよいこと: Grefx に近づいたことを停止条件にすること、旧 B_total から `s_ref` だけを引くこと、外挿値を μ や U の代わりに使うこと、資格不足のまま「line implicit が原因で格子差が消えた」と報告すること。

呼び出し側の前提への異議: 「旧式は Grefx の格子誤差に Gref の解き残しを加えている」という説明は受け入れない。旧式はもともと**運用上の頑健性を含む予算**であり、真の格子誤差の式ではない（plan `:596`）。新式への変更は合理的だが、評価する問いが変わることを明記する。
