# codex 判断依頼 — 壁熱流束は `q_recon` か `q_eff` か (2026-09-21)

対象 plan: [`plans/active/boundary-conjugate-heat-transfer.md`](../../plans/active/boundary-conjugate-heat-transfer.md) §4.3
依頼種別: 自由形式の判断依頼 (両論併記を禁じ、推奨を 1 つに絞らせた)
プロンプト: `scratchpad/codex_flux2.txt`
きっかけ: ユーザ指摘「`-Fw/A` ≡ 壁面自身の粘性流束。**CFD で使う熱流束が全てではないのか**」

## こちらが提示した事実

- `viscousFlux_d.cu:610-633` より `Fw` は壁境界半割面を通る全エネルギー流束、`-Fw/A` ≡ `q_recon`
  (実測でも相対 1.2e-8 で一致)。
- `nodeWallDirichlet_d.cu:95-102` より `Rraw` は壁ノードの全エネルギー残差で Dirichlet ピンが捨てる値。
  `q_eff = (Rraw-Fw)/A` = (内部双対面の正味流束)/A。
- 反力 `(Q_eff-Q_recon)/Q_recon` は **格子 (340/480/680) にも反復 (20k→200k) にも動かず +2.4〜2.5 %**。
- **収束するスラブ** (`case/52.conjugate_slab/run_0005_qeff`、解析解あり) では反力 −5.2e-6 で 3 定義が一致。
- 全体収支の積分はこちらの精度不足 (ΔH が格子間で 3.3 % ばらつく一方 `Q_recon` は 0.08 %) で裁けない。

## 結論 (codex)

**(a) 報告も (b) 連成も `q_eff` に統一。差 2.5 % は保存性欠陥として不確かさに計上しない。**

1. **争点は「`Fw` を残差に加えたあと、その残差行を捨てている」こと。** `Fw` だけでは
   *境界条件の適用まで終えた離散系*の熱交換を表さない (`nodeWallDirichlet_d.cu:95`)。
2. 内部面からの正味流入を `I` とすると `Rraw = I + Fw`、`C = -Rraw`、
   **`Q_fluid→solid = -Fw - C = I = A q_eff`**。この `C` は**指定温度を保つための離散的な熱浴の反力**で、
   **CHT ではその熱浴の役割を固体が担う**。だから固体には反力込みの熱量を渡す必要がある
   (`conjugateWall.cpp:209` の実装がこの式)。
3. 「CFD が実際に使った熱流束が全て」への答え: **境界条件による残差の置換まで含めて
   「実際に使った」と数える必要がある**。`Fw` は組み立て途中に使われるが、壁エネルギー行は
   そのまま解かれていない。`q_eff` から `Fw` が消えるのは、指定温度の自由度を消去した系で
   その温度を支える熱負荷を回収するため。
4. **2.5 % を誤差幅にしない理由**: `Rraw` 自体にゼロへ収束する要請が無い。自由な内部ノードの残差と、
   温度拘束された壁ノードの反力は別物。スラブで一致するのは**そのケースで 2 つの評価が整合した証拠**
   であって、一般に反力がゼロになる証拠ではない。格子・反復で差が残ることも保存性欠陥を示さない。
   → **差は熱流束評価の整合性診断として記録し、±2.5 % には変換しない。**
5. **ただし選択と精度は別**: 全翼 run が `NOT CONVERGED (stalled/plateau)` なので、
   `ΔH = Q_eff` は不動点を仮定した式であり現状は内部 CV の残差総和が残る。
   `Q_recon` の格子間差 0.08 % は真値への誤差が 0.08 % という意味ではない。
6. **報告名**: 「**保存的な実効壁熱流束 `iface_q_eff` (固体向き正、未収束の暫定値)**」。

## 当方の採否

**全面採用。こちらの傾き (「`q_recon` を報告すべき」) を撤回する。**

決め手は 2.: **連成では固体が熱浴そのもの**なので、熱浴の反力は「ピンが壊したエネルギー」ではなく
「固体が供給/吸収した熱」である。非連成 (実測 Tw を課す) の場合も、その $T_w$ を保っていたのは
実機の金属と冷却剤であり、報告が測った $h$ はまさにその収支から出ている。よって `q_eff` が
実測と対応する量で一貫する。

これに伴い撤回するもの:

- 「反力は未収束の残差だから、2.5 % を収束の誤差幅として持ち回る」→ **撤回**。整合性診断として記録する。
- 「全体収支は `q_recon` を支持する格子がある」→ **撤回**。こちらの ΔH 積分の 3 % ノイズを読んでいた。
- plan §4.3 の正本選択は**変更なし** (維持が推奨された)。

## 残作業 (plan §5.1 に登録)

- 報告の呼称を「保存的な実効壁熱流束 (未収束の暫定値)」に統一する。
- `q_eff - q_recon` を**整合性診断**として `check_cht_balance.py` に出力させる (誤差幅にはしない)。
- 翼で残差が落ちきる構成を見つけない限り、壁熱流束の絶対精度は検証済みと言えない。
