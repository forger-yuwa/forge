## 1. 目的

node (median-dual) の**対流再構成まわりで SU2 と食い違っている点**を直す。
起票のきっかけは case/46 の機体ベース発散だったが、**調査の結果それは本 plan の対象ではなくなった** (§4.5/§4.6)。
現在の主題は (a) **リミッタの評価点が再構成点とずれている**こと、(b) **再構成・更新の汎用セーフガードが無い**ことの 2 つ。

## 2. スコープ

**対象**: リミッタの評価点、再構成値の物理性検査、更新率の上限、非物理状態のロールバック。
**対象外**: 粘性流束・勾配計算そのもの・壁関数 (`wallTreatmentSST`)・cell モード。
`mesh.bndFirstOrder` は**使用禁止**なので代替案に含めない (粘性応力まで壊し、疑似 2D で全域に効く)。

## 3. 関連 docs と前提

- 壁ノードの Dirichlet は 3 点セット (状態ピン / 残差射影 / 陰解法 Jacobian 行) で
  [`methods/boundary.md`](../../methods/boundary.md) に記載済み。**本件はその 3 点とは別の層 (対流流束の再構成)**。
- 壁半割面の質量流束が 0 であることは [`discretization-node-boundary-ghostless.md`](discretization-node-boundary-ghostless.md) §4 の前提そのもの。

## 4. 設計方針

### 4.1 現行の実装 (実測で確認済み)

壁ノードまわりは 4 層に分かれている。

| 層 | 実装 | 壁ノードでの挙動 |
| --- | --- | --- |
| 状態 | `cuda_forge/nodeWallDirichlet_d.cu` `enforceWallNoSlip_d` | `roU*` と `U*` を 0 に、KE を `roe` から除去 |
| 残差 | 同 `zeroWallDirichletResiduals_d` | `res_roUx/roUy/roUz` (+SST `res_roOmega`、等温 `res_roe`) を 0 に。**`res_ro` は射影しない** |
| 境界半割面 | `convection/convectiveFlux_boundary_d.inc.cuh` | `mdot = sss*(ro_R*Vn_m)` で bvar 状態のみ・**再構成なし**。no-slip なら `Vn_m = 0` で**質量流束は厳密 0** |
| 内部面 | `convection/convectiveFlux_common_d.cuh` `interp_MUSCL_2nd` | `phif = phiC + psi*(grad . cpd)`。node では `cpd` = エッジ中点 (`convectiveFlux_d.cu` の `rem = (discretization=="node") ? 1 : 0`、**config で切れない**) |

**噛み合っていない**: 状態層が `phiC = 0` にしても、内部面の再構成は勾配を足す。
壁のすぐ外が高速なら勾配は大きく、面に有限の速度が乗る。
境界半割面は塞がっているので、内部面の正味が流出ならその CV は補充されずに空になる。

**1 次ではこの問題が起きない**: `phif = phiC = 0` なので、風上が壁ノード側のとき `rho u = 0` となり、
**壁 CV は対流で質量を失えない** (流れが入る向きなら隣接側が風上になるので、入ることはある)。
2 次はこの性質を壊す。

**forge には再構成値の物理性検査もクランプも無い** (確認済み: `convectiveFlux_slau_d.inc.cuh` で
`ro_L`/`P_L` は `interp_dispatch` の結果をそのまま使う。`contactBlend` は組成勾配向けの別機構で既定 off)。

### 4.2 症状と証拠 (case/46, 2 次元平面, node, SST, frozen_tp)

正本は [`tooling-nozzle-sern-3d.md`](tooling-nozzle-sern-3d.md) §4.15.6 / §4.15.7。要点:

- 機体ベース (厚さ 0.02 H、流れに正対する no-slip 壁) の壁ノードで、再構成が面に **457 m/s** を置く
  (節点値は 0)。実装式をそのまま再現した厳密値。
- その 9 ノードの密度が 27 step で **0.00358 → 0.00003 (120 倍減)**、圧力 1159 → 32 Pa。
  周囲のベース帯 41 ノードの平均圧力は 7 % しか落ちない = **壁 CV だけが空になる**。
- **1 次は 40 step 完全に不動**。`nodeWallDirichlet: 0` でも 40 step 完走 (ただし壁ノードが 1500 m/s で動く)。
- **CFL 律速でない** (1/10 の CFL で 6.6 倍の step)。**`implicitRelax` は 1.4 倍の延命のみ**。
- **格子を細かくすると悪化する**: 壁 CV 体積 3.3 倍減 → 落ちる step 2.8 倍早い (ほぼ体積比例)。

**測定器**: `solver_density_cuda/tools/check_wall_cv_drain.py` (本 plan で追加済み)。
**ふるいであって予測器ではない**: 風上化を含まないので偽陽性がある
(本ツールが最大と出したカウル後縁ノードは実際には密度が上がる。判定は `ro` の時系列で行う)。

### 4.3 他ケースとの比較

`case/18.backstep` (後ろ向きステップ = 同じく流れに正対する壁) の node・2 次・`nodeWallDirichlet: 1` の
**収束解**では、速度ピン壁ノード 474 個の漏れは最大 4.1 /s で、1 ms 以内に空になるノードは 0。
SERN のベースは 1.2e5 /s。**同じ機構が 5 桁弱い**。
ただし**収束解と過渡の比較なので公平ではない** (収束解では正味流束は定義上ほぼ 0)。
言えるのは「backstep はその状態に到達できている、SERN のベースは到達前に空になる」まで。

### 4.4 SU2 の実装 (`.external/su2-src`, v8.5.0 を実際に読んだ結果)

**結論: 壁ノードの扱いは forge とほぼ同じで、ここに差は無い。** 期待していた「SU2 は壁ノードを特別扱いしている」は**外れ**だった。

| 論点 | SU2 | forge |
| --- | --- | --- |
| no-slip の課し方 | **強制 Dirichlet のみ** (`CNSSolver.cpp:508-525` `SetVelocity_Old` + `LinSysRes(iPoint,iDim+1)=0`、`:577-581` `Jacobian.DeleteValsRowi`) | 同型 (状態ピン + 残差射影 + 陰解法の行単位化) |
| 壁面からの対流質量流束 | 静止格子では **0** (`Res_Conv = 0`、書き込みはエネルギー行のみ `:543`) | 0 (bvar の `Vn_m = 0`) |
| **壁ノードの連続の式** | **固定しない** (`LinSysRes(iPoint,0)` に触る処理は存在しない) | **固定しない** |
| **壁ノードでの MUSCL** | **特別扱いも除外も存在しない** (`Upwind_Residual` に境界判定なし。`GetPhysicalBoundary` は JST のセンサーにしか使われない) | 同じく特別扱いなし |
| 再構成の目標点 | **辺の中点** (`CEulerSolver.cpp:1925` `V_i + 0.5*lim_i*Project_Grad_i`) | **辺の中点** (node は `g_reconEdgeMid` 常時 1) |
| **リミッタの評価点** | **辺の中点** (`computeLimiters_impl.hpp:175-180` `dist_ij = 0.5*(coord_j-coord_i)`) = **再構成点と厳密一致** | **双対面重心** = **不一致** ← 唯一の実質的な差 |

**forge に無い SU2 の汎用セーフガード (壁専用ではない)**:

1. **再構成の物理性検査 → そのエッジを 20 反復 1 次に固定** (`CEulerSolver.cpp:1940-1962` + `CFlowVariable.hpp:80-87` `UpdateNonPhysicalEdgeCounter`)。負の p/rho/音速のみ。
2. **密度・エネルギー更新率の自動 under-relaxation** (`CFVMFlowSolverBase.inl:599-630`、既定 `MAX_UPDATE_FLOW = 0.2`) = 1 非線形反復で 20 % 以上変われない。
3. **非物理状態になった点の解を前反復値へ巻き戻す** (`CNSVariable.cpp:151-178`)。

### 4.5 診断の座標を間違えていた (2026-09-19, codex plan レビュー Critical 1)

**§4.5/§4.6 の当初の数値と結論は、測定器がソルバと違う点で再構成していたため無効**だった。

`CELLS/centCoords` は**実行時にノード座標へ置換される** (`main.cpp` の `nodeValueAtNode` → `mesh.cpp`。
`run_0208/forge_run.log` に `centCoords <- node coords for 62317 CVs (max centroid shift 0.03593721241)` と出ている)。
メッシュ HDF5 の `centCoords` をそのまま使うと別の点で再構成したことになる。訂正後:

| 診断量 | 誤 (centCoords) | 正 (ノード座標) |
| --- | --- | --- |
| 62100→62107 の `Ux_L` | 457.42 m/s | **651.77 m/s** |
| 62104→62111 の `Ux_L` | 365.77 m/s | **521.17 m/s** |
| `Ux_L / (0.5 x Ux_隣接)` | 0.70 | **0.999996** |
| 中点とのずれが辺長 1 % 超の内部面 | 58899 (47.7 %) | **48328 (39.1 %)** |

**なお成立するもの**: 再構成は片側勾配の理論値 `0.5 x u_隣接` に**厳密に一致**しており、
SU2 が出す値と同じ。**「壁ノードからの再構成が異常」という当初仮説の棄却は維持する**
(ただし「SU2 より保守的 (0.70 倍)」は誤りで、**一致**が正しい)。

**崩れたもの**: 「非物理な再構成はベース無しでも同じように出るから原因ではない」は**誤り**。
`tools/check_face_reconstruction.py` (本 plan で作り直し) でノード座標で数え直すと:

| step | ベース有り `run_0208` | ベース無し `run_0209` |
| --- | --- | --- |
| 1 | 0 面 (最小 1056.56 Pa) | 0 面 (最小 1375.90 Pa) |
| 5 | 0 面 (429.45 Pa) | 0 面 |
| **6** | **1 面 (−66.78 Pa)** | 0 面 |
| 27 / 40 | **3 面 (−296.25 Pa)** | **0 面 (40 step 通して)** |

**対照は完全にクリーンで、ベース run だけが非物理な再構成を作る。**
最初に出るのは x = −0.05 m (入口面) の 47703→47702 で、ベース自身の面も step 27 には負になる。
**SU2 の `bad_recon` 検査はベース run で発火し、対照では発火しない** → §4.4 の (1) は
「本件に無関係」ではなく**直接の候補**。

### 4.6 「1 次は壁 CV が質量を失えない」も誤り (codex Major 2)

SLAU の質量流束は `convectiveFlux_slau_d.inc.cuh:493`:

```
mdot = sss*0.5f*((ro_L*(Vn_p+Vn_hat_p_abs)+ro_R*(Vn_m-Vn_hat_m_abs)) - chi/(c_diss)*P_del)
```

**左右の速度がともに 0 でも、圧力差 `P_del` だけで質量が動く**。
したがって「1 次では壁ノード側が風上のとき `rho u = 0` なので壁 CV は質量を失えない (一方弁)」という
説明は成り立たない。**1 次が 40 step 不動だったのは観測事実として残すが、その理由づけは撤回する。**
原因は SLAU 面流束の符号付き総和・密度残差・陰的補正量で論じ直すこと。

同じ理由で、旧 `check_wall_cv_drain.py` の質量流束見積り (`rho_L u_L . S` を積むだけ) は
**座標と欠落項の二重に不正確**だったので削除し、`check_face_reconstruction.py`
(再構成状態の物理性のみを、実装と同じ式・同じ座標で検査) に置き換えた。

### 4.7 SU2 との比較で言えることの範囲 (codex Major 3)

§4.4 の比較表で引いた `CNSSolver.cpp:508` は**熱流束壁**の処理で、対象 run は**等温壁**。
SU2 の `BC_Isothermal_Wall_Generic` は温度差から熱流束を作りエネルギー残差と Jacobian に加える
(行削除は運動量のみ)。forge は `nodeWallDirichlet_d.cu` で `T/roe/P` をピンし等温壁のエネルギー残差を 0 にする。
**熱的閉包は同型ではない。**

また SU2 の Venkatakrishnan の平滑化係数は参照長さと設定係数依存 (`CLimiterDetails.hpp`)、
forge は局所 `volume` 依存で、勾配の作り方も未比較。
**「同条件なら SU2 のリミッタは 1」「SU2 より小さい」はソースの形だけからは言えない。**

言えるのは**構造上の一致に限る**: 速度 Dirichlet / 連続の式を解く / 内部辺を再構成する / 再構成の目標点は辺中点。
**同一メッシュ・対応 BC で実際に走らせるまで SU2 の成否は予測しない。**

### 4.8 W1 の設計: 再構成増分の列挙と共通化 (2026-09-19, codex Major 5 対応)

**ずれは 2 成分ある。** 「座標を揃える」だけでは足りない。

**(1) 流束側が実際に適用する増分** (`convectiveFlux_common_d.cuh` の `interp_dispatch`)。
`phi_face = phiC + psi * Δ` の Δ は `convMethod` で違う:

| `convMethod` | 関数 | 増分 Δ |
| --- | --- | --- |
| 0 / −1 | `interp_1stUp` | **0** (`return phiC`。ψ は無関係) |
| 1 | `interp_MUSCL_2nd` | `g · cpd` |
| **2** | `interp_MUSCL_3rd` | `0.5·k·(phiD − phiC) + (1−k)·(g · cpd)`, k = 1/3 ← **隣接値差を含む** |
| その他 | `interp_MINMOD` | 別式 (`f`・`dcc` を使う) |

`cpd` は目標点までのオフセットで、**node では常に `±0.5·dcc` (エッジ中点)**
(`convectiveFlux_d.cu` の `rem = (discretization=="node") ? 1 : 0`)、cell では `pc[ip] − cc[ic]` (双対面重心)。

**(2) リミッタ側が評価する増分**:

| 経路 | 評価点 | 増分 |
| --- | --- | --- |
| 通常 (`limiter_d.cu` の `limiter_r1_fused5_d` pass2) | `pc[ip] − cc[ic0]` (**双対面重心**) | `g · dcp` のみ |
| 周期 node (`limiterPeriodic_d.cuh`) | 同じく `pc[ip] − cc[ic0]` | `g · dcp` のみ (`SCALED` 版は `× inv_ref`) |

**したがって node では、点が違う (重心 vs 中点) うえに、`convMethod: 2` では形も違う**
(リミッタは隣接値差の項を**一度も見ない**)。SU2 はリミッタ側でも `umusclProjection` を適用して形まで揃えている
(`computeLimiters_impl.hpp`)。

**設計**: 増分を作る関数を 1 つにし、流束とリミッタが**同じ関数・同じ引数**で呼ぶ。

```
__device__ flow_float recon_increment(int scheme, flow_float phiC, flow_float phiD,
                                      flow_float gx, flow_float gy, flow_float gz,
                                      flow_float cpdx, flow_float cpdy, flow_float cpdz, ...);
// 流束:     phi_face = phiC + psi * recon_increment(...)
// リミッタ: delta_m  = recon_increment(...)   ← psi を求める材料
```

**必要な入力はすべて揃っている**: リミッタ pass2 で partner は pass1 と同じ一行
`ic1 = plane_cells[2*ip+0] + plane_cells[2*ip+1] - ic0` で取れる。`phiD = Q[k][ic1]` も pass1 で既読。
エッジ中点オフセットは `0.5*(cc[ic1] − cc[ic0])`。

**float32 の桁落ちも同時に直す** (codex Major 5): 現行は `Qt = qc + g·dcp` を作ってから `Qt − qc` を渡しており、
**足して引く往復で桁を落としている**。共通関数は Δ を直接返すのでこの往復が消える。
変更前後で `Δ` の相対差を float32/float64 で測って記録する。

**周期経路も同じ関数を通す** (`limiterPeriodic_d.cuh`)。`SCALED` 版のスケーリングは Δ を作った後に掛ける。
**cell は対象外** (cell の目標点は双対面重心のままで整合しているので、分岐を維持する)。

### 4.9 W1 の合否ゲート (実装前に固定, codex Major 6/7 対応)

**Barth と Venkatakrishnan で要求を分ける。**

| ゲート | 対象 | 要求 |
| --- | --- | --- |
| G1 厳密有界性 | `limiter: 1` (Barth) | 再構成した面値が**近傍の min/max を外れる面が 0** |
| G2 平滑化込みの逸脱 | `limiter: 2` (Venkatakrishnan) | 逸脱は許すが**逸脱量が改修前より減る**こと。`eps2 = volume` が正なので厳密有界は保証されない (例: `δmin=0, δm=−1, volume=1` で ψ=1/3) |
| G3 正値性 | 両方 | `check_face_reconstruction.py` の VERDICT。**W1 単独で 0 になることは要求しない** (それは W2 の役割) |
| G4 解の非退行 | 両方 | `check_field_regress.py --boundary` をノイズ床基準で。**リミッタが強く効くので解は動きうる** — 動いたら SU2 クロスチェック (`procedures/su2-cross-check.md`) で是非を決める |

**共通 IC と設定差分を固定する**: `run_0205/res_0.h5` を共通初期場に、`output.level: 2`・`outStepInterval: 1`。
差分は `space.limiter` と新キーのみ。メッシュ品質 VERDICT・全残差・`check_quasisteady.py` を毎回貼る。

**標準ケース回帰** (`procedures/verification/README.md` から具体名で指定):
`case/05.sod_shock_tube` (衝撃波)、`case/36.passive_pseudoshock_control` (擬似衝撃波・node 壁)、

### 4.10 W1 の実装と A/B の実測 (2026-09-19)

**実装**: `space.limiterMatchRecon` (既定 0)。`limiter_d.cu` の `limiter_r1_fused5_d` と
`limiterPeriodic_d.cuh` の `limiter_psi_merged_d` に分岐を足し、`=1` のとき

- 目標点を **node ならエッジ中点** (`0.5*(cc[ic1]-cc[ic0])`) にする
- `convMethod: 2` なら **隣接値差の項も含めた増分**にする (`interp_MUSCL_3rd` と同形)
- 増分 `delta` を**直接**作る (`Qt` を経由しないので float32 の足して引く桁落ちが無い)

周期経路には `plane_cells` を引数追加して partner を取れるようにした。cell は分岐を維持。

**既定パスの非退行**: 変更を外した HEAD の worktree でバイナリを作って比較した。
**ビット同一ではないが、差は run 間非決定性の水準**:

| | 同一バイナリの反復 (ノイズ床) | 変更前バイナリ vs `mr:0` |
| --- | --- | --- |
| step 1 `ro` | 1.96e-07 | 4.51e-07 |
| step 10 `ro` | 8.08e-07 | 6.52e-07 |
| step 27 `ro` | 7.90e-07 | 1.34e-06 |

(この診断 run は step 28 で発散するのでノイズがカオス的に増幅する。`limiter_P` はノイズ床自体が 0.96。)
**カーネル引数を足すとレジスタ割り当てと命令スケジューリングが変わる**ので、式が同一でもビット同一にはならない。
コード中の「ビット不変」というコメントは実測に合わせて「式は変更前と同一」に訂正した。

**A/B (共通初期場 `run_0205/res_0.h5`, cfl 1.0, 2 次)**:

| 構成 | 結果 |

### 4.11 W1b: Venkatakrishnan が効かない理由と対策案 (2026-09-19, ユーザ指摘)

**`limiter: 2` (Venkatakrishnan) は生産既定なので、そこで効かないと意味がない** (`procedures/solver-settings.md`)。
§4.10 で Barth だけが通った理由を実装から特定した。

**forge の実装** (`limiterFunctions_d.cuh`):

```
flow_float K = 1.f;
flow_float eps2 = K*K*K*volume;        // ← 次元: [m^3]。delta は変数の次元 (kg/m^3, Pa, m/s)
```

**`eps2` が変数と無関係な次元で、しかも `K = 1` 固定**。SU2 は `eps2 = (K * RefElemLength)^3` で
**K の既定が 0.05** (`CConfig.cpp`)、かつ**変数を無次元化して解く**ので `delta` が O(1)。
forge は**次元付きの変数**にそのまま当てている。

**実測 (ベース壁ノード 62104, `run_0218` step 20)**:

| 量 | 値 |
| --- | --- |
| `ro` (節点) | 1.297e-03 |
| 近傍 `ro` の min / max | 1.297e-03 (**自分が最小**) / 1.022e-02 |
| `delta_p_min = qmin − qc` | **0** (ちょうど 0) |
| `delta_m` (62103 への再構成増分) | −4.586e-05 |
| `eps2 = volume` | 1.024e-06 → **ε = 1.012e-03 = `ro` の 78 %** |
| **Barth ψ** | `min(1, 0/−4.6e-5)` = **0** (完全に 1 次化) |
| **Venkatakrishnan ψ** | `ε²/(2Δ⁻²+ε²)` = 1.024e-6/(4.21e-9+1.024e-6) = **0.9959** (ほぼ無制限) |

**平滑化の閾値 ε が変数の値そのものと同じ大きさ**なので、密度は**どこでも制限されない**。
`P` (O(1e3)) では ε=1e-3 が無視できるので ψ_P は正常に 0 まで落ちる — **変数ごとに挙動がまるで違う**のが症状。
(なお現行式は ψ > 1 を返すことがあり [実測 1.0035]、呼び出し側の `min(max(·,0),1)` で潰している。)

**対策案 (未確定・codex レビューに出す)**:

- **案 S (無次元化)**: `delta` を変数ごとの基準値で割ってから Venkatakrishnan に渡す。
  **forge には既に同じものがある** — `passiveLimiter_d.cuh` の `limiter_r1_scaled_d` が
  `phi_ref = max(|Qc|, |Qmax|, |Qmin|, phi_floor)` で無次元化している (**受動スカラー専用**)。
  流れ 5 変数に同じ扱いを入れるだけ。上の実測に当てると
  `Δ̂⁻ = 4.586e-5/1.022e-2 = 4.49e-3` → ψ = 1.02e-6/(4.03e-5+1.02e-6) = **0.0247** (Barth の 0 に近い)。
- **案 K (係数を出す)**: `K` を config キーにする (SU2 の `VENKAT_LIMITER_COEFF` 相当)。
  既定 1.0 で現行維持、0.05 (SU2 既定) を試す。`K=0.05` なら `eps2` は 8000 分の 1。
- **両方**: 無次元化したうえで K を選べるようにするのが SU2 に最も近い。

**論点**: (i) 基準値を `max(|Qc|,|Qmax|,|Qmin|)` にするか別の取り方にするか (速度は 0 を跨ぐ・`phi_floor` の決め方)、
(ii) `eps2` の**局所 volume 依存**を残すか SU2 のような大域参照長にするか、
(iii) `limiterMatchRecon` と同じキーに畳むか別キーにするか (前者は評価点、後者は平滑化閾値で**独立な欠陥**)、
(iv) 既定を変えるか opt-in に留めるか (解が動く)。

### 4.13 W1b の確定設計 (codex M3/M4 の対案を採用)

**案 S の単純移植 (`phi_ref = max(|Qc|,|Qmax|,|Qmin|)`) は不採用** (codex M4):
速度に当てると**一様な速度加算だけで平滑化強度が変わる** (参照 0.02 → 1000.02 で ψ が 2e-6 → 0.9998)。

**採用する形**:

1. **無次元化は run 中固定の物理参照値で行う**: `rho_ref`, `p_ref` (**ゲージ差圧でなく絶対圧力**), `a_ref` (音速)。
   **速度 3 成分は共通の `a_ref`** で割る (成分ごとの局所絶対値を使わない)。
2. **ε̂² = (K · h_i / L_ref)³** とする。`h_i` は**平面・軸対称では半径重み前の面積の平方根**、**3D では体積の立方根**。
   周期 node では合併 CV に対応させる。<br>
   理由 (codex M3): 現行の `volume` は共通の長さ尺度でない — 平面 2D は面積×単位厚み、
   **軸対称はさらに半径を掛ける** (同じ増分でも半径で平滑化が変わる)、周期 node は合併体積。
3. **`K` を config キーにする**。ただし **SU2 の 0.05 をそのまま移植しない**:
   SU2 は `RefElemLength = 1.0` で閾値 1.25e-4、対象ノードで forge の K だけ合わせると約 1.28e-10 で **約 100 万倍違う**。
   forge の式に合わせた値を実測で決める。
4. **式の整理**: 現行 `venkata_limiter` は分子分母に余分な `delta_m` 因子を持つ。約分する。
   **`K=0, δp=0, δm=1e-19` で `0/0 → NaN`** を codex が float32 で再現しており、これも同時に潰す。
5. **`limiterMatchRecon` とは別キー**にする (評価点と平滑化閾値は**独立な欠陥**)。既定は現行維持の opt-in から始める。

**必須の試験**: 単位変換 (SI ↔ 別単位)、相似拡大 (メッシュを一律スケール)、格子細分。
**軸対称**で半径依存が消えることを確認する。

**§4.11 の「密度はどこでも制限されない」も過大**だった (codex M4): `run_0218` step 20 で
`limiter_ro < 0.9` が **4661 / 62317 節点**、最小 **0.002031**。正しくは
**「局所状態と尺度によって効き方が不適切になる」**。

### 4.15 W1 の共通化と範囲限定を実装 (2026-09-19, codex M7 対応) + **A/B の土台が不適切と判明**

**実装**:

**ところが、リファクタで A/B の結果が変わった**:

| --- | --- | --- |

### 4.18 リミッタの形を 3 つ比べた: **比の形が最良** (2026-09-19, ユーザ問い「これしかないのか」)

### 4.21 スケール不変性 (相似拡大 ×1024) — 旧 Venkatakrishnan はメッシュを大きくすると**リミッタが消える**

**設計**: メッシュ座標を **2 の冪 (×1024)** で拡大すれば float32 で丸めが一切出ない
(`COORD`/`centCoords`/`surfArea`/`surfVect`/`wall_dist` ×S、平面 2D なので `volume` (=面積·奥行 1) ×S²)。
状態場 (ρ,u,P) は示強量なので不変。**スケール不変なリミッタなら ψ はビット同一になる**はずで、
差が出ればそれは 100 % リミッタのスケール依存性である。1 step・`output.level 2` の `limiter_*` を比較
(`run_0261`–`run_0268`)。**物理的な相似は不要** — ψ は状態と幾何だけで決まり粘性項を通らない。

| 構成 | ψ の最大差 | ψ が変わったノード | ψ_ro 平均 (ref → ×1024) |
| --- | --- | --- | --- |
| A ① 生産既定 | **9.98e-01** | **58761 / 62069** | 0.9718 → **0.99998** |
| B 評価点一致 (旧 Venkat) | **9.98e-01** | **58919 / 62069** | 0.9715 → **0.99998** |
| C ② 無次元化 | **0** | **0** | 0.7101 → 0.7101 |
| D ③ 比の形 | **0** | **0** | 0.7101 → 0.7101 |

**旧 Venkatakrishnan は ×1024 で実質 OFF になる** (ψ→1)。`eps2 = K³·V` が面積 (2D) と共に ×2²⁰ 増え、
分子分母を支配して常に ψ≈1 を返すため。**②③ はビット同一** = 厳密にスケール不変。
**格子細分は別に測る** (codex plan-3 Major 5 を採用): ×1024 が示したのは「この入力・この 1 回の評価で
スケール依存性を分離できた」ことだけで、格子細分は (a) 解像度が上がって場そのものが変わる、
(b) h_i と L_ref の比が変わる、の 2 つが同時に効くので同じ軸ではない。**§5.1 の残作業に残す**。
なお ②③ は ψ_ro 平均 0.710 と旧式 0.972 より**大幅に強く効いている** — 目的量への影響は §4.17/§4.18 の通り +0.026 %。

**結論 (確定)**:

- **生産既定のリミッタは `ro` と `Uy` で有界性を破っている** (8478 / 21460 面側)。
- **② と ③ と Barth はいずれも全変数で逸脱 0** (許容幅 1e-5×scale の下で)。**②と③は有界性でもスケール不変性でも区別できない**。
  **ただし「② が厳密有界性を保証する」は数学的に誤り** (codex plan-3 Major 3): 局所極値で δp=0 のとき
  ψ = ε²/(2δm²+ε²) > 0 なので δm<0 なら下限を割る。実例 `qc=qmin=0.01, δm=-0.1, ε²=0.01` → ψ=0.3333, 面値 **−0.0233**。
  上の 0 は「**この入力で許容幅を超える逸脱が無かった**」という実測であって、普遍的な保証ではない。
- **W1 は `Ux`/`P` を、W1b は `ro`/`Uy` を直す**。単独ではどちらも 5 変数を満たせない (束で入れる)。
- したがって **②と③の選択は「基準値が要るかどうか」で決まる → ③ 比の形を採る** (§4.18)。

**MLP (§4.19) の位置づけも変わる**: ③ で全変数が既に 0 なので、**MLP が改善する余地は有界性には無い**。
MLP の利点があるとすれば衝撃波近傍の挙動や収束性であって、本 plan の G1 では測れない。**W2b は据え置き**。

**③ 比の形を棄却する理由 (§4.18 の推奨を撤回)**: 比の形 ψ(y) は y=Δ₊/Δ₋ だけの関数なので、**滑らか域でリミッタが切れない**。
Venkatakrishnan の ε² は「Δ が十分小さければ ψ→1 にして定常収束を妨げない」ためにあるのであって、それを捨てると
Barth と同じ非平滑性が残り、**定常残差の床が上がる** (case/44 で実測)。「基準値が要らない」という ③ の利点は
この代償に見合わない。**§4.18 の「③ が最良」は撤回**する。

**SU2 との対応 — 構造だけが共通で、閾値は同じでない** (codex plan-3 Major 4 を採用・前版の記述は誤り):
SU2 は `eps2 = (L·K)³`, `L = REF_ELEM_LENGTH` = **1.0** (`Common/src/CConfig.cpp:5021`。前版が書いた 0.1 は誤り),
`K = VENKAT_LIMITER_COEFF` = 0.05 (`CConfig.cpp:2006`) なので **ε² = 1.25e-4、√ε² ≈ 1.118e-2**。
前版の「SU2 既定は Δ_無次元 ≲ 3.5e-4 で ②(K=1) の 1.9e-4 と同程度」は**両方とも誤り**なので撤回する。
さらに SU2 の ε² は**大域定数**だが forge の ② は**局所 h_i³ 依存** (`limiter_d.cu:341`) で、格子依存性も同じではない。

**言えるのはここまで**: 「**無次元の増分に平滑化項 ε² を加える**」という構造が共通で、SU2 が SI 次元のまま
同じ式を使っても壊れないのは**解を無次元化して解いているから**である。forge は SI 次元のままなので
同じ式が壊れた — これが ① の欠陥の説明になる。**② の妥当性は forge 自身の精度・収束・格子感度で判断し、
「SU2 と閾値が同程度」を採用理由には使わない**。

**⚠ 上の表の 05 / 09 は最初の実施時点では ② を実行していなかった** (codex plan-3 Critical 1):

### 4.23 W2 設計: 面単位の非物理フォールバック (SU2 `bad_recon` 相当)

**位置づけ**: リミッタ (§4.13/§4.22) が保証するのは**近傍に対する有界性**であって**物理性ではない**。
有界性の前提は「ノード自身の値が健全」であること — 更新が負圧を作り EOS 床が洗浄した直後のような局面では
ψ がいくら正しくても守れない。そこを**面単位**で止めるのが本節。§4.22 の ② と**重複しない**。

**SU2 の実物** (`CEulerSolver.cpp:1946-1965`, `CFlowVariable.hpp:72-87`):

```cpp
bool bad_recon = neg_sound_speed || neg_pres_or_rho_i || neg_pres_or_rho_j;
bad_recon = nodes->UpdateNonPhysicalEdgeCounter(iEdge, bad_recon);
numerics->SetPrimitive(bad_recon ? V_i : Primitive_i, bad_recon ? V_j : Primitive_j);
// UpdateNonPhysicalEdgeCounter: 真なら counter=21、毎回 max(0, counter-1)、counter>0 を返す
```

- `neg_sound_speed` は **Roe 平均**の全エンタルピーと速度から `(γ-1)(H_roe - ½|u_roe|²) < 0` で判定する。
- 復帰先は**両側とも**セル平均値 `V_i`/`V_j` (片側だけ戻すのではない)。
- カウンタは `int8_t` の**辺ごと**。**辺を訪れるたびに減る**ので、陰解法の内部反復でも自然に期限切れする。

**forge 側の設計**:

| 項目 | 方針 | 理由 |
| --- | --- | --- |
| 判定 | `ro_L,ro_R ≤ roMin` / `P_L,P_R ≤ pMin` (既存の EOS 床キー [[eos-pressure-floor-config]]) + ρ/P の非有限。**速度の非有限は未検査 (残作業)** | forge は SI 次元なので固定 0 でなく設定済みの床を使う。**節点状態そのものが不正なら 1 次に戻しても不正なまま** — W2 は更新による状態破壊の代替にはならない (codex plan-3 Major 8) |
| 音速判定 | **第 1 段では入れない**。ρ/P で SERN ベースが捕まるかを先に見る | TP・多成分で Roe 平均エンタルピーを作るのは高く、効果が確認できてから |
| 復帰 | その面の **`conv_scheme` を局所的に −1** にして流れ 5 変数をセル値に戻す | **⚠ 「全変数が同じ `interp_dispatch` を通るので自動で整合する」は誤り** (codex plan-3 Major 8)。化学種の面値共有は S3 経路 (`speciesTransport_d.cu:802`)、凝縮モーメントは `condensationTransport_d.cu:300` で受動種経路と従来 1 次移流に分かれる。ΣY の保証は各側の正規化にも依存し、「片側だけ戻すと必ず ΣY≠1」も誤り。**第 1 段は node + SLAU/SLAU2 に限定**し、対応する S2/S3・受動種・凝縮設定を列挙してから広げる |
| ヒステリシス | 面ごと `int8_t` カウンタ。発火で `N+1`、訪問ごと `max(0, c-1)`、`c>0` の間 1 次 | SU2 と同一。毎 step 2次↔1次が振れるのを防ぐ |
| config | `space.badReconFallback: 0` (既定 OFF) / `N` = ヒステリシス回数 (SU2 相当は 20) | **既定 OFF の opt-in で入れる**。A/B が済むまで生産既定を動かさない |
| 診断 | 発火した face-side 数を既存の `g_*` 診断と同じ形で間隔出力 | 「発火しているのか」を推測でなく数で言うため |

**適用範囲**: 内部面のみ (`convectiveFlux_slau_d.inc.cuh` の主ループ)。境界半割面は再構成していない
([[node-boundary-flux-structure]]) ので対象外。

**⚠ 前提条件 (実装前に確認すること)**: §4.5 で「ベース run でのみ発火し対照では発火しない」と書いたのは
**削除済みの `check_wall_cv_drain.py` による後処理**の結果で、§4.20 で後処理の再構成判定は信用できないと
分かっている。**まず `limiterDiag` と同じ形でカーネル内に発火カウンタだけを入れ、ベース run と対照で
本当に差が出るかを測ってから**フォールバック本体を入れる。差が出ないなら W2 は本件の候補から外す。

### 4.24 W2 の結果 — **発火は実在したが、フォールバックしても発散は変わらない** (2026-09-19)

§4.23 の設計どおり実装した (`space.badReconDiag: N` で計測、`space.badReconFallback: N` で本体。**既定はどちらも 0**)。

**V1 発火の記録 — PASS** (対照の発火有無は中止条件にしない、§6.4 改訂): `run_0269_v1_base` (ベース有り) / `run_0270_v1_nobase` (対照)。5 flux 呼び出しごとの窓:

| 窓 (call) | ベース有り | 対照 (ベース無し) |
| --- | --- | --- |
| 5 | 0 / 617930 | 0 / 615490 |
| 10 | **5** (`P` 5, `ro` 0) | 0 |
| 15 / 20 | **5** (`P` 5, `ro` 0) | 0 |
| 25 | **6** (`P` 6, `ro` 1) | 0 |
| 30 / 35 | (step 28 で NaN 停止) | 0 |

**発火は NaN (step 28) より先行する** (call 10 ≒ step 2 付近) ので、V1 の合格条件「発火が発散に先行する」を満たす。
**ベースでのみ発火し対照は 40 step 全窓でゼロ**。§4.5 の後処理による同趣旨の主張は §4.20 で無効になっていたが、
**カーネル内で測り直して同じ結論が立った**。あわせて **`P` が先 (call 10)・`ro` は 18 step 遅れて (call 25)** と分かり、
detectNaN が `ro` を指すのは終端症状だという [[detectnan-reports-symptom-not-cause]] の見立てと整合する。

**V2 既定不変 — PASS** (ノイズ床基準。§6.4 改訂後の判定): 既定 (`0`) のまま同一入力を新旧バイナリで走らせ、**同一バイナリ 2 回走のノイズ床と比べた**
([[noise-floor-both-sides]])。`case/05` `run_0023/0024_v2_bitcheck`: 旧 vs 新 1.19e-4 < ノイズ床 **1.51e-4**。
`case/44` `run_0494/0495_v2_bitcheck`: 旧 vs 新 2.81e-4 < ノイズ床 **3.38e-4** (状態量は ρ 4.6e-6 / P 6.0e-7 / T 4.3e-6 で
いずれもノイズと同桁)。**「ビット同一」という §6.4 の文言は誤り** — `case/05` の node 3D periodic は
同一バイナリでも 1.5e-4 再現しない。判定はノイズ床比較が正しい。

**V3 介入の効果 — 負の結果**: `run_0271_v3_base_fb20` (`badReconFallback: 20`, SU2 相当) / `run_0272_v3_base_fb5` (`5`)。
`active1st` は 5→6 と V1 で数えた面とちょうど同数が 1 次に落ちており **機構は設計どおり動いている**。
それでも判定軸のいずれも改善しない: **非物理面の数は減らず** (call 25 で 6 のまま)、**有限状態は維持されず**、
**残差も下がらず**、NaN は `run_0208`/`run_0269` と同じ step 28 で出る。
(生存 step の一致だけを根拠にはしない — §4.15 でその指標は棄却済み。ここでは**非物理面の数が減らない**ことが主根拠。)
**カウンタの単位は流束評価回数**だが、block-DPLUR は固定残差の線形 sweep (`main.cpp:1456`) で `nStepInner` ごとに
流束を再評価しないので**実質は外部 step 単位**であり、28 step の run では `N=20` の期限切れは一度も起きていない。

**結論**: **非物理な再構成はベース発散の駆動要因ではなく、NaN の 18 step 前に現れる症状**である。
W2 は本件の候補から外す。コードは **opt-in (既定 0) のまま残置**する — V1 の計測器は
「発火しているのか」を推測でなく数で言える唯一の手段で、他ケースの切り分けに使える
([[optin-retained-is-not-rejected]] のとおり opt-in 残置は削除対象ではない)。V4 は V3 が負なので実施しない。

**次にどこを見るか**: ベース発散の駆動は再構成の外にある。残るのは
(a) 壁 Dirichlet の残差射影が `res_ro` を射影しない ([[node-boundary-flux-structure]]) こと、
(b) ベース角の幾何そのもの (格子細分は §4.5 の `run_0213` で**悪化**した)、
(c) SST の隔離更新チャネル ([[implicit-cfl-ceiling-eos-floor]] で lowMachPrecond 併用が破綻したのと同じ経路)。

   — 収束解で発動し続けるなら解を歪めている。
