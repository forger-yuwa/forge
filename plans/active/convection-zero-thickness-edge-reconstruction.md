## 1. 目的

旧テンソル積メッシャ (g3) の SERN で、厚さ 0 のカウル後縁の近くの内部節点が非物理に冷え、m10_on で温度床 50 K に到達して評価が不成立になっている (R7b 4-2)。
m6_on では node + SLAU の 2 次再構成の速度の外挿 (後流側の面で全エンタルピーを運び出す) が局所の残差を維持する機序を診断済み。m10_on の移動先 (517199) に対して端近傍の処置が十分かは未確認 (§6.1 で判別)。端の近傍に限った局所の扱いで床到達を無くし、旧メッシャのまま m10_on の評価を成立させ、設計ループ (R7b) を再開できる状態にする。

## 2. スコープ

- **やる**: 自由端の近傍集合 $S_2$ の定義と作成、$S_2$ の速度の再構成を節点値にする opt-in の処置 (node + SLAU)、判別 A/B、恒久対策としての受入れ (m10_on の評価成立・他作動点の感度・設計差の取り直し・他ケースの回帰)。
- **やらない**: 床値の変更・床ゲートの除外・`bndFirstOrder`・勾配配列のゼロ化・節点 ID を固定した生産処置・全ケースのリミッタ変更・流れの閾値検出器やスキーム変更 (第一手として却下、§4)。有限厚の全ヘキサとの差を温度誤差の上限と呼ぶこと。

## 3. 関連 docs と前提

- 診断の事実 (codex diagnose 2026-10-08 [記録](../../notes/reviews/2026-10-08-sern-te-reconstruction-fix-diagnose.md) と、そのブリーフ `notes/reviews/briefs/2026-10-08-sern-te-reconstruction-fix.md`):
  m6_on で後流側の 1 面の速度の外挿 (節点値 10 → 再構成 1333 m/s) が低温を維持し、その 1 面を節点値にすると低温が消える (力の感度は許容の 1/100 以下)。m10_on では同じ 1 面の介入で冷点が隣の第 1 層 (517199) へ移り、
  その冷却は EOS 前の更新 (対流を含む残差) で説明できる (`notes/investigations/2026-10-05-sern-r7a/R5H_M10_LEDGER100.txt`、EOS の上書きは call 50 で −1.746e-2 J/kg に対し更新 −1.499e3 J/kg)。
- 現行のリミッタは近傍の成分別 min/max を参照する (`limiter_d.cu:323`)。診断介入は `FORGE_DIAG_FACE_VEL_CELL` (`convectiveFlux_slau_d.inc.cuh:279`、1 面・片側の速度だけ)。
- SLAU は残差を `atomicAdd` で組み立てる (`convectiveFlux_slau_d.inc.cuh:661`) — 長時間の run 全体のビット不変は保証できない。

## 4. 設計方針

**判断: 2026-10-08 codex (diagnose) — 全件採用。第一手は幾何で限定した速度の再構成の抑制 (診断案)。流れの閾値検出器・成分別上下限制約・流束の変更は第一手として却下** (今回必要なのは「範囲逸脱」の実証で、大きい速度の外挿だけではその証拠にならない。成分別に有界でも別々に再構成した ρ・U・P からのエネルギー流束の妥当性は保証されない)。

- **ユーザ判断 (2026-10-08): 端の判定はソルバでなく前処理で行う**。前処理の道具 (`solver_density_cuda/tools/mark_zero_thickness_edges.py`) が変換済みの入力 h5 に**節点フィールド $w$ (`w_recon_vel`、0〜1)** を書き、
  ソルバはそれを読んで速度の再構成を $\mathbf u_f = \mathbf u_i + w_i\,\psi\nabla\mathbf u_i\cdot\mathbf r_{if}$ にするだけ ($w = 1$ で今と同じ、$w = 0$ で節点値)。理由: ソルバに形状の判定を持たせない、
  カウル後縁以外 (スリット・ベースの角・ユーザ指定の領域) にも同じ仕組みで使える、フィールドを ParaView で確かめられる、0〜1 の重みに拡張できる、周期の対応点などの整合を前処理で保証できる。
  初版の道具は下の E・$S_2$ の規則で $w \in \{0, 1\}$ を書く (**生産は 0/1 に限定**。中間値は「速度外挿量を縮める数値的な重み」で物理係数ではなく、熱力学的整合・正値性を保証しないので、使うなら生成則の受入れを別途行う)。
  **前処理の契約 (2026-10-08 codex diagnose、Major 4 件・Minor 1 件を全件採用)**:
  - **読取元**: $w$ は必ず `meshFileName` の `/AUX/w_recon_vel` (ghost を含まない実節点順の 1 次元配列) から読む。`VALUE` には置かない。同一格子の継続 (`restart_field`) は宛先の $w$ を保持し、別格子 (`interp_field`) では宛先で作り直す。prepare では品質確認用の cell 格子でなく**最終の node 変換の後**に生成する。
  - **格子との結び付け**: 道具は属性に**格子署名**と**$w$ のハッシュ**を書き、ソルバは読込時に両方を再計算して照合し、不一致なら時間更新前に起動時エラー。署名の入力 = 離散化・次元・節点順の座標・内部面の接続・各境界グループの physID と元の境界面接続 (`vizBfaceNodes`)。`VALUE`・`/AUX` は除外。
    直列化 = 配列名・shape・規定の型 (float64/int64 に正規化)・little-endian の値。**HDF5 ファイル全体のハッシュは使わない** (圧縮・配置で変わる)。ハッシュ関数は C++ と Python で同一に実装できる 64 bit FNV-1a (偶発的な取り違えの検出が目的)。
    $w$ 単独のハッシュを格子整合の証明にしない (同数節点の別番号付けを通してしまう)。タグ名 → physID の対応は明示的に受け取り、属性に記録する。
  - **`stage_key`・来歴**: 属性の値を転記せず、各段の起動前にその段が読む `meshFileName` から格子署名と $w$ のハッシュを再計算して入れる (道具の `mesh_signature()`・`field_hash()` を共用)。
  - **検査の分担**: ソルバは汎用の契約 (長さ・有限・$0 \le w \le 1$、clamp して受理しない、格子署名・ハッシュの照合) だけを検査し、**$w \equiv 1$ は受理する** (0 の節点を要求しない)。タグ不在・境界面の接続なし・E が空・発火数の検査は道具と SERN の prepare が行う。
  - **ParaView**: 道具は `/AUX/w_recon_vel` を `Center='Node'` で参照する XDMF も出す (現行の XDMF は `VALUE/` しか参照しない、`output.cpp:247`)。
- **端集合 E** (前処理の道具の規則): 指定した板の上下の壁面タグ (SERN では `cowl_in` と `cowl_out`) が**同じ節点 ID を共有する自由端**の節点。後縁の線と露出した側端を含む。座標一致だけで別 ID の節点を結合しない (旧メッシャの共有処理は `mesh_sern3d.py:271`)。
  **抽出の入力 (2026-10-08 plan レビュー M1)**: node 変換後の境界面の `iNodes` は 1 節点だけなので使えない — **元の境界面の接続 `vizBfaceNodes`** (`gmshReader.hpp:2339/2686`) から作る。3D は 2 タグの primal 境界面が**共有する辺**の節点、2D は 2 タグの境界線が**共有する端点**。
  指定したタグが格子に無い・境界面の接続が無い・E が空のときは**起動時エラー** (正常な空集合と混同しない。空マスクの旧経路は「opt-in していない」場合だけ)。実格子 (run_1055) で **517160・517199 ∈ $S_2$** を必須条件とする。
- **$S_2$**: 内部面の接続グラフで E から距離 2 以下の節点 (グラフの 2 リング。壁法線の「2 層」とは区別)。記録上 517199 は壁点から 1 接続、517160 は 2 接続なので両方を含む診断用の最小候補。
- **作用 (適用位置は codex diagnose 2026-10-08 Major 3 で確定)**: 勾配項に $w$ を掛けるのではなく、既存の診断介入 `FORGE_DIAG_FACE_VEL_CELL` と同じ位置 (`contactBlend`・`lowMachThornber`・フォールバックの**後**) で、補正済みの旧面速度 $\mathbf u_{f,old}$ を節点速度へ縮める:
  $w = 1$ は $\mathbf u_{f,old}$ をそのまま (演算しない)、$w = 0$ は $\mathbf u_i$ を直接代入、$0 < w < 1$ は $\mathbf u_i + w(\mathbf u_{f,old} - \mathbf u_i)$。初版 ($w \in \{0,1\}$) では、$w = 0$ の節点 ($S_2$) に接する全内部面で、**その節点側だけ** Ux・Uy・Uz の面値が節点値になる (速度だけ局所 1 次。node モードの双対 CV はコード上「セル」と呼ばれるので、既存の診断介入名 `FORGE_DIAG_FACE_VEL_CELL` の「セル値」= 節点値) (相手も $S_2$ なら両側)。勾配配列・粘性・壁 BC・密度/圧力/組成の再構成は変えない。速度二乗・面エンタルピー・質量流束を計算する前に適用し、1 つの面流束を両節点へ逆符号で加算 (保存)。
- **適用範囲**: node + SLAU の**明示 opt-in** (設定キーは $w$ フィールドの有効化とフィールド名だけ。旧案の `{tags, rings}` はソルバの設定でなく前処理の道具・問題 YAML の入力)。無効なら旧経路 (面値・面流束はビット不変)。E が空の拒否は前処理の道具が行う。
  **初版の契約 (同 M2)**: 有効化 + 周期境界は起動時エラー (周期節点は別 ID・別接続面で同じ DOF として更新されるので、内部面グラフの距離では対応点のマスクが一致する保証がない、`periodicNode_d.cuh:14`)。cell モード・SLAU 以外も起動時エラー。軸対称は未検証なので起動時エラー (保証するときは 2D の端定義と軸ピンとの交差を検査してから)。未検証の構成を空マスクの回帰で受入れ済みにしない。
- **設計チェーンへの配線 (同 M3)**: 問題 YAML → 各段の solver config → 起動時の実効値 → `stage_manifest` の区間識別 (`stage_key` に有効状態・正規化したタグ・リング数を含める) → metrics/設計 DB の来歴 (マスクの節点数とメッシュの識別情報も)。
  現行の `stage_key()` は ON/OFF・リング数で区間が分かれない (読み取り実行で確認、`stage_manifest.py:266`)、runner は固定テンプレートから `space` を作る (`runner_sern.py:346`、`runner_sern3d.py:359`)。
  **OFF → ON とリング数の変更で区間が分離すること、旧評価の持ち越し禁止が働くこと**を試験で確かめる。
- **記録**: E・$S_2$ の節点数・面数、実座標での広がり、対象体積を起動ログと出力に。異方格子なのでリング数だけでは物理的な広さを表せない。
- **段階**: (1) 判別 A/B (§6.1) で「$S_2$・速度限定の処置で 517199 と 517160 の両方を救えるか」を判別 → (2) 合格なら恒久対策としての受入れ (§6.2)。短い診断だけでは R7b を再開しない。

### 4.1 対立仮説: 角部の勾配の算出に難がある (ユーザ指摘 2026-10-08、未検証)

> 「そもそも角部の勾配の算出方法に難がある可能性は無いのかな」

これまでの診断は「この勾配で外挿すると冷える」までで、**勾配そのものの妥当性は調べていない**。記録の数字が手がかりになる:
m6_on の冷点 (2026-09-27 の帳簿) で、再構成先は辺の中点 ($\mathbf u_f = \mathbf u_i + \psi\nabla\mathbf u_i\cdot(\mathbf x_j - \mathbf x_i)/2$)、
$u_i \approx 10$ m/s・$u_f = 1333$ m/s・$\psi = 0.28$ から $\nabla u_i\cdot(\mathbf x_j - \mathbf x_i) \approx 2\times1323/0.28 \approx 9450$ m/s に対し、相手との実際の差は約 1490 m/s
(相手 $|U| \approx 1500$ m/s) — **その辺の方向の勾配が実際の差の約 6 倍** (記録の速度が大きさか成分かは未確認なので目安)。
候補 (未検証): node の勾配は LSQ (`gradLSQ: 2`、境界は内部隣接のみ) で、冷点の近傍に後縁の壁節点 (no-slip で $u = 0$、上下の流れが共有する 1 点) や高 AR の壁層の短い辺が入り、
当てはめがそれらに引きずられて下流の辺の方向に過大な勾配が出る。Venkat は近傍全体の成分別 min/max しか見ないので、近傍の範囲 (〜1500 m/s) に収まる外挿は止めない。
**これが主因なら、端近傍の速度を 1 次に落とす処置 (§4) は症状を抑える処置で、本筋は勾配の算出 (特異な角での LSQ の近傍・重み) かリミッタの辺方向の検査の修正**になり、カウル後縁以外の鋭い角にも効きうる。
**判別の測定 (数値の変更なし、§6.1 の A/B より前)**: run_1055 の場から 1 step、勾配 (`dUxdx` ほか)・リミッタを `extraFields` で出力し、冷点と周辺の節点で
LSQ の近傍ごとの位置・値・寄与、辺ごとの比 $\nabla u_i\cdot(\mathbf x_j - \mathbf x_i)/(u_j - u_i)$、LSQ と Green–Gauss の勾配の比較を後処理で出す。
判定と、勾配側の修正に切り替えるかは上位に諮る (諮問中)。実装中の前処理の道具と $w$ の仕組みは、勾配側の修正でも範囲の指定に使えるので継続する。


## 5. 実装ステップ

1. 前処理の道具 `mark_zero_thickness_edges.py`: 端集合 E と $S_2$ の作成 (`vizBfaceNodes` と内部面の接続から)、入力 h5 へ $w$ を書く。ソルバ側は $w$ の読み込み・検証・デバイス配列。**小さな検査を最初に**: 共有端・座標一致の別 ID・有限厚・端なし・2D の端点・タグ誤記・周期/cell/非 SLAU/軸対称の拒否。
2. 設定キーと設計チェーンへの配線 (問題 YAML [前処理の入力: タグ・rings] → prepare で道具を呼んで $w$ を書く → config [有効・フィールド名] → 実効値 → `stage_key`・metrics・設計 DB の来歴 [フィールドの sha256 を含む])。区間分離と持ち越し禁止の試験。
3. **計測の実装 (同 M4、A/B より前)**: 帳簿で状態更新・壁/軸/等温ピン・EOS・BC の差分を分けて出す (今は `entry` と `after_eos_bc` の間にまとまっている、`main.cpp:1975/2018`)、面帳簿の上限超過 (200000 件で切り詰め、`convectiveFlux_d.cu:665/721`) は判定不能にする、
   長期 run 用に**毎更新の床補正の事象のカウンタ** (plan レビュー 2 回目 M3): TP の温度床は温度反転関数の内部 (`DEPVAR_TMIN` = 50 を渡した float Newton と double 研磨の**各反復**でクランプ、`dependentVariables_d.cu:172`・`thermo_d.cuh:660/748`) にあり、最終の `roe` は別の場所で再構成される — **反復中のクランプの回数は数えない**。
数えるのは「更新後の保存量の内部エネルギーが温度下限に対応する内部エネルギー $e(\rho, Y, T_{min})$ を下回り、最終状態を床へ補正した事象」で、**実節点・更新単位**の件数・補正量 $\Delta(\rho E)$・発生位置 (ghost は別集計)。
通常の丸め (補正量が丸め上限以下) は数えない。正常状態・床未満・下限近傍の単体試験を付ける。既存の `floor_gate()` は最終保存場だけを見る (`sern_gates.py:200`)。
4. SLAU 流束カーネルで、既存の診断介入 `FORGE_DIAG_FACE_VEL_CELL` と同じ位置で補正済みの旧面速度を節点速度へ $w$ で縮める (§4 の作用)。無効時と $w \equiv 1$ で面値がビット同一。起動ログ。
5. 判別 A/B の再生・退避・帳簿 (§6.1)。
6. 恒久対策の受入れ (§6.2)。
