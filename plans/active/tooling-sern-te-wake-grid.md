## 1. 目的

旧メッシャはカウル後縁の下流の中間線を MOC の自由境界の終端角 θ_b (−40.2°) で引くので、境界層の格子線が後縁で約 36° 折れ、
m10_on で後縁の 1 節点が温度床 50 K に張り付いて評価が成立しない。中間線を後縁の接線から出して 1.0 H で旧線へ戻す局所変形
(`mesh3d.te_wake_blend_H: 1.0`) は、g3 で冷点を消した (起点 plan §6.0 の結果 A)。これを**生産の評価系列に入れてよい状態**にする
(格子感度・来歴・旧評価の扱い・2D)。

## 4. 設計方針

**判断: 2026-10-08 codex (diagnose) `2026-10-08-te-wake-ab-result-diagnose.md`、Major 4・Minor 2 を全件採用。**

- **既定は 0 のまま**。生産候補の YAML に `mesh3d.te_wake_blend_H: 1.0` を明示する。メッシャの既定を 1.0 に変えない (評価系列の識別が格子の変更を区別できるまで)。
- **格子の来歴と評価方式の識別を分ける (codex plan レビュー 2026-10-08 M3)**:
  - **来歴** (`stage_key`・個別評価の `metrics.json`): 実入力格子から再計算した格子署名 (`mark_zero_thickness_edges.mesh_signature`、座標・接続) と**双対幾何 (`PLANES/surfVect`・`CELLS/volume`) のハッシュ**。
    座標・接続の署名だけでは変換器の修正 (`ef74e342`) のような双対幾何の変更を検出できない (run_1055 と A′ は署名が同じで双対の閉性が FAIL/PASS)。属性の転記でなく再計算する。
  - **学習可否** (設計 DB・`driver_sern` の `_learnable`): **評価方式の識別** = 曲線版・blend の指定 ($L_b$)・格子生成のレシピ (格子水準・メッシャの版)・変換器の版・離散化。実格子署名は設計点ごとに変わるので学習条件に使わない (使うと系列が設計点ごとに分裂する)。
    「同じ方式の異なる設計点は一緒に学習できる」「同じ形状でも旧方式・来歴不明は除外」の両方を試験する。旧データは削除せず保持し、修正後の学習系列への混入を止める。旧評価の持ち越しの承認 (§6 #6・#7) は対象と根拠を別項目で記録する。
- **床の判定 (codex plan レビュー M1・M2)**: 生産受入れでは**毎更新の床事象のカウンタ**を使う。
  **定義のやり直し (2026-10-08 codex diagnose [`notes/reviews/2026-10-08-floor-counter-definition-diagnose.md`](../../notes/reviews/2026-10-08-floor-counter-definition-diagnose.md)、全件採用)**:
  定常陰解法 (と陽解法) では EOS の床は作業配列だけを書き換え、commit は床前の基準 `roN/roeN + dq` (`update_d.cu:301`) なので、旧定義「最終状態を床へ補正した事象 (commit に残った補正)」は構造上 0 件になる (実装担当のコード読み、`dependentVariables_d.cu:76/172/203/207/209`・`main.cpp:2032/2491/2647`)。
  → **数えるのは「EOS の床を必要とした事象」**。床の種類別の述語で数え、補正量は付帯情報:
  温度 = EOS と同じ密度・組成での $e_{in} < e_{mix}(T_{min})$ (と最終温度が下限)、密度 = $\rho_{in} < $ `roMin`、圧力 = クランプ直前の $P_{raw} < $ `pMin` (TP の圧力床の量は $\Delta P$、その操作による直接の $\Delta(\rho E)$ は 0)。
  「roe の再構成差が丸め上限を超えたら温度床」は採らない (密度床と通常の再構成誤差が混入する)。**補正量による足切りはしない** (除外閾値 0。述語が成立した事象だけを数えるので、通常状態の再構成の丸めは数えない)。
  **時点の契約**: 判定区間 $(a, b]$ は、区間の入口 $Q_a$ を別枠で記録し、$Q_{a+1} \ldots Q_b$ を次の EOS の入力で、**最後の $Q_b$ は終了時の監査**で確かめる。すべて「境界ピン (no-slip・軸・等温壁) の後・EOS の床の前」という同じ状態で判定する。
  終了時の監査は**コピー上で同じ前処理を再現し同じ判定関数を適用**する (通常の配列に EOS を再適用しない)。初期化・restart の EOS は別記録にし、リセットで痕跡を失わせない。同じ状態を二重に数えない。定常の `nStepInner` の sweep は保存量を更新しないので更新として数えない (`main.cpp:2177`)。
  経路 (定常陰解法・陽解法・dual-time) ごとに計測の時点を登録し、**未検証の経路を 0 件で通さない**。床の近傍 ($T \le T_{min} + 1$ K) は件数・位置を別に記録し (補助)、床事象と混ぜない。
  **本 plan では床の commit の仕方 (非保持) は変えない** (更新則を変え、既存の A/B と共通バイナリの前提を壊す)。是非は別 plan。床使用 0 を実証できなければ受入れ不可。床使用 0 でも起動過渡の影響まで消えたとは主張しない。
  保存標本の「床近傍 0 節点」を「全更新の床補正 0 件」と読み替えない。**カウンタを先に実装・検証し、その共通バイナリで g3 (B を初期場に継続) と g4 の判定区間を取る** (既存の run_1079 の CSV は保存時点の値で、過去の更新事象を復元できない)。
  記録形式を固定する: 更新単位 (外側の step と内反復)・実節点数・計測区間 (開始・終了 step)・restart 時のリセット・欠測/切り詰め/整数あふれの検出。**記録が無いことを 0 件として扱わない**。
  **生産ゲートに接続する**: 現行の `floor_gate()` (`sern_gates.py:200`) は最後の HDF5 だけを見るので、判定区間中に床補正され最終場で回復した評価が通りうる。新しい生産系列ではカウンタを必須入力にし、`sern_gates` → `metrics.json` → 台帳の採否まで接続する。
  「途中で 1 件・最終場は正常」「記録の欠落」「restart 後の区間の欠落」を拒否する試験を付ける。
- **力の差の扱い**: g3 の B − A′ (末尾 20 標本の平均差: C_T +6.54e-7、C_T_with_shear −7.90e-5、C_L +2.08e-4、C_M −4.53e-3) は離散化の変更への応答であって、冷点除去の物理効果とは認定しない。
  採用判断に原因別の分解は要らない。旧 m10_on は床到達で評価不成立のまま。m6_on・m4_off の旧評価の持ち越しは §6 #6・#7 で判定する (格子感度の許容を持ち越し基準に使わない)。
- **監視領域**: 起点 plan §6.2 の $R_{TE}$・$R_{SE}$ と復帰区間 RET (x ∈ [L_cowl, L_cowl + L_b]) と全域。マスク外周 $R_M$ は $w$ 固有なので外す。
- **2D (codex plan レビュー M4)**: 2D メッシャ (`mesh_sern.py:256`) も同じ作り。同じ方式を実装し、2D で独立に検証する (3D の成功で 2D を受理しない)。
  既存の道具は 3D 専用 (`te_wake_grid_check._read_h5` はヘキサ接続を要求、`te_monitor.py` は側端を z = 0.1 m に固定) なので、2D 用の格子品質・双対閉性・実際の辺の角度・層厚の検査と、**形状から監視領域を生成する処理**を作る。
  2D に存在しない側端の領域は明示的に対象外とし、必要な領域が空なら判定不能にする。初期場の作り方・2D runner のオプションの受け渡し・既定 0 の不変試験まで登録する。
