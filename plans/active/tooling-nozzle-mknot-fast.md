## 1. 目的

要求カードの M_knot の自動選択 (既定) は、1 枚の生成に 45〜97 分かかる (AWS、評価の並列 1/1; plan mknot-auto §5.1 #6)。パラスタのたびにこの時間がかかる
(ユーザ 2026-10-15「パラスタする度に時間かかっちゃうならしんどい」「劇的に早くしてほしい」)。選び方も、2N のゲート・窓の拡張・同点の規則・境目の二分法と
積み上がり、説明も保守も重い (ユーザ 2026-10-15「フローがややこしくなって結構しんどい」)。
**目標**: M_K の選び方を単純にし、カード 1 枚の M_knot の部分 (r_t の固定点のやり直しを含む) を AWS A で 600 s 以下にする。

## 4. 設計方針 (2026-10-15、ユーザ決定「a」で書き直し)

### 4.0 ユーザの決定と経緯

- 2026-10-15、ユーザ「そもそもが、もっと荒くていいのでは」「規則というかメッシュのつもり」「フローがややこしくなって結構しんどい」「五次多項式では厳しいのだったっけ」→
  単一の五次式は M5 以上で成立しない (knot 則が要る、M_K はその第 2 の自由度) と説明し、A (単純化、2〜3 分) と B (今の仕組みを保ち 15〜20 分) を示した。**ユーザ「a」**。
- 長さを固定したカードでは L_c は `from_length` で決まり、残る軸の Mach 則の自由度は M_K だけ (ユーザ「掃引するのってmkだけでいいの？」への回答)。
- 単純化で失うもの (受け入れた限界、ユーザに説明済み): 生産の網を 2 倍 (4800) にして初めて現れる不成立の検出 (旧の試験 (n)(o) の型)。実データでは境目は 2400 → 4800 で 0.00125 しか動いていない (case/70、1 形状)。
  過去の上位の指摘 (2026-10-15 diagnose M1・plan 段 M1) はこの限界の指摘で、ユーザの判断で受け入れる。plan 段 M1 の「谷の取り違え」は §4.1 の 3 で安く防ぐ。

### 4.1 規則 `coarse_min_theta_v2` (2026-10-15 plan 段レビュー v2 の Major 4 件・Minor 2 件を反映)

格子は整数 k で持ち、M_K = 0.05·k とする (浮動小数の比較で隣を決めない)。

1. **粗い掃引**: M_A < 0.05·k < M_d かつ両端から 0.05 以上内側の全部の k を、粗い網 `N_s` = 生産の `n_axis_inv` / 4 (2400 なら 600) と長さの許容差 `L_s` = 0.1 r_t
   (事前に固定。カードの値は 600 では全点未収束: §3) で 1 回評価する。制約は今と同じ (`feasibility_reasons`; θ_max が有限でも `ok=False` の行はある)。
   各行に `L_c`・符号つきの長さの残差・停止の理由を記録する。
2. **候補の区間**: 粗い網で成立し、両隣 (k ± 1) も成立している k を候補にし、k が連続する候補を 1 つの**候補の区間**にまとめる (不成立の点で分かれる)。
   真の境目は成立の端の点より外にあるので、候補から境目まで 0.05 以上 (旧の ΔM_safe と同じ値)。境目までの**推定の距離** = 候補から最も近い粗い網の不成立の格子点までの距離 − 0.05 (粗い網の値、記録用と同点の決着用)。
3. **谷の代表**: 候補の区間ごとに、粗い網の θ_max の局所極小を全部拾う (区間の端も、内側の隣と比べて極小なら含める。等しい値が続く平らな列は 1 つの極小とし、代表は推定の距離が最大の点、同じなら小さい k)。
4. **谷ごとの確認とずらし** (生産の網 `N_p`、カードの `L_total_tol`): 代表 v で v と v ± 1 を評価する。
   - v が不成立 → その谷を捨てる。
   - v と両隣が成立 → その谷の最終の代表は v。
   - v が成立で片側だけ不成立 → 反対側へ 1 つずらす (移動先が同じ候補の区間にあるときだけ)。移動先で同じ確認を、その谷で最大 3 回まで繰り返す (初回の確認 + 移動 3 回)。区間の外に出る・両側が不成立・上限 → その谷を捨てる。
5. **谷の比較**: 最終の代表が決まった谷の中で、`N_p` の θ_max の全体の最小を θ_min とし、θ_max ≤ θ_min + 0.01° の谷を同点の集合として**一度だけ**作る (逐次比較しない)。
   その中で推定の距離が最大、同じなら θ_max が小さい、同じなら M_K が小さい谷を選ぶ。最終の代表が 1 つも無ければ例外 (表つき)。
6. 粗い網で成立点が無い・粗い網の長さ合わせが全点で未収束・候補が無いときは例外 (表つき)。黙って旧の規則に落ちない。

- 出す値は格子の値 (例 2.05)。
- **r_t の固定点と終了の条件**: 最初の r_t で 1〜5 を回して M_K を固定 → r_t の固定点 → 出力と**同じ実効の入力** (r_t・`n_axis_inv`・`L_total_tol`・`x_end_margin`・その他 geometry) で 1〜5 を回し直す。
  終了は「固定点の残差が許容内」かつ「その選択が使った M_K と一致」。違えば新しい M_K で固定点をやり直す (上限 2 回、超えたら例外)。
  自動調整 (`n_axis_inv` の倍化・`L_total_tol` の緩和: `wt_card.py:1706`、最終の壁の判定の後の `x_end_margin` の変更: `wt_card.py:2024`) が起きたら、それまでの評価を全部捨て、
  `N_s`・`N_p`・許容差・並列の数を設定し直して最初の選択からやり直す (今の `wt_card.py:2012` と同じ)。評価の使い回しは同じ実効の入力の中だけ。
- **計時**: M_knot に起因する再固定点・再評価の時間を全部 `M_knot_rule.elapsed_s` に入れる (今は `wt_card.py:1972` で加算の後に `solve_loop` を呼ぶので抜ける)。カード全体の時間も並べて記録する。
- 旧の規則 `min_theta_max_v1` の関数 (`select_mknot`・`resolution_gate`) と試験はモジュールに残す (カードからは呼ばない)。消すかは別に決める。

### 4.2 評価を軽くする (数値は変えない)

- **メモリ**: `evaluate_mknot` が `from_length` の反復で呼ばれた逆 MOC の結果 (網 `levels` を含む) を全部捕捉している (`mknot_select.py:164`)。`from_length` が正常に返すのは
  最後の評価 (plan 段レビューが 256 通りの残差系列で確認)。捕捉を最後の 2 つに限る (外を採ったら今と同じく行の `error` で不成立)。
- **並列**: 並列の数 = min(CPU 数, 4, ⌊0.7 × MemAvailable / 1 評価のピーク⌋)。ピークは捕捉の変更の後に `N_s`・`N_p` で測り直した値で持つ。算出が 0 なら評価の前に例外、
  MemAvailable が取れなければ 1。環境変数 `FORGE_MKNOT_WORKERS` で上限を下げられる (手元の PC の事故 2026-10-14 の再発防止)。

### 4.3 後回し

- 逆 MOC の内部点の計算 (`interior_vec`、時間の 6〜7 割) の JIT 化: 生産の壁の数値が丸めの範囲で変わるので別の受入が要る (#4)。
- パラスタの間は `overrides: {geometry.M_knot: <値>}` で固定し、最後の候補だけ自動にする手順を skill に書く (#5)。

- 粗い網は候補づくりだけで 2400/4800 のゲートを残す案 → plan 段レビュー GO-with-changes (谷の取り違え・最初の組と最終の保証の分離・V4 の完了条件)。見込み 15〜20 分。ユーザが A を選んだので不採用。

## 6. 検証

事前登録 (2026-10-15、ユーザ決定「a」の後):

- **V1 規則の単体試験** (合成の評価関数、CFD 0 step):
  (i) 谷の取り違え (plan 段 M1): 粗い網 `min(15 + 2(M−2)², 15.02 + 400(M−3.45)²)`、生産の網で第 2 項の定数 14.5 → 3.45。
  (ii) ずらした後の比較 (plan 段 v2 M2): 粗い網は (i) と同じ、生産の網 `min(15 + 400(M−2)², 15.02 + 400(M−3.45)²)`、生産の網で 1.95 だけ不成立 → 3.45 (2.05・16.00° を返さない)。
  (iii) 確認の分岐: 中心だけ不成立 → 谷を捨てる、両側不成立 → 捨てる、片側不成立 → 反対側へずらして再評価、移動先が区間の外 → 捨てる、移動 3 回の上限 → 捨てる、全部の谷を捨てる → 例外。
  (iv) 候補の区間: 成立の端の点を候補にしない、`M=[2.00, 2.05, 3.00, 3.05]`・`θ=[15, 16, 17, 18]` (2 区間) で両方の区間の極小 (2.00 と 3.00) を拾う、平らな列は 1 つの極小、入力の順を逆にしても同じ結果。
  (v) 同点: θ が 15.000・15.009・15.018° で推定の距離 0.1・0.2・0.3 → 同点の集合は {15.000, 15.009} (15.018 は θ_min + 0.01 を超える) → 距離 0.2 の谷。評価の順を変えても同じ。
  (vi) 粗い網で成立点なし・長さ合わせの全点未収束・候補なし → 例外。
  (vii) 捕捉を 2 つに限っても、`time_s` を除く数値・判定の欄が今と完全に一致 (実際の問題 (a) の 3 点、N 600・2400)、捕捉の外を採るように細工すると行の `error`・`ok=False` で選択に使われない。
