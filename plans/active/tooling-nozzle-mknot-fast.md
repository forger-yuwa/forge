## 1. 目的

要求カードの M_knot の自動選択 (既定) は、1 枚の生成に 45〜97 分かかる (AWS、評価の並列 1/1; plan mknot-auto §5.1 #6)。パラスタのたびにこの時間がかかる
(ユーザ 2026-10-15「パラスタする度に時間かかっちゃうならしんどい」「劇的に早くしてほしい」)。選び方も、2N のゲート・窓の拡張・同点の規則・境目の二分法と
積み上がり、説明も保守も重い (ユーザ 2026-10-15「フローがややこしくなって結構しんどい」)。
**目標**: M_K の選び方を単純にし、カード 1 枚の M_knot の部分 (r_t の固定点のやり直しを含む) を AWS A で 600 s 以下にする。

### 4.1 規則 `coarse_min_theta_v2` (2026-10-15 plan 段レビュー v2 の Major 4 件・Minor 2 件を反映)

格子は整数 k で持ち、M_K = 0.05·k とする (浮動小数の比較で隣を決めない)。

1. **粗い掃引**: M_A < 0.05·k < M_d かつ両端から 0.05 以上内側の全部の k を、粗い網 `N_s` = 生産の `n_axis_inv` / 4 (2400 なら 600) と長さの許容差 `L_s` = 0.1 r_t
   (事前に固定。カードの値は 600 では全点未収束: §3) で 1 回評価する。制約は今と同じ (`feasibility_reasons`; θ_max が有限でも `ok=False` の行はある)。
   各行に `L_c`・符号つきの長さの残差・停止の理由を記録する。
2. **候補の区間**: 粗い網で成立し、両隣 (k ± 1) も成立している k を候補にし、k が連続する候補を 1 つの**候補の区間**にまとめる (不成立の点で分かれる)。
   真の境目は成立の端の点より外にあるので、候補から境目まで 0.05 以上 (旧の ΔM_safe と同じ値)。境目までの**推定の距離** = 候補から最も近い粗い網の不成立の格子点までの距離 − 0.05 (粗い網の値、記録用と同点の決着用)。
3. **谷の代表**: 候補の区間ごとに、粗い網の θ_max の局所極小を全部拾う (区間の端も、内側の隣と比べて極小なら含める。等しい値が続く平らな列は 1 つの極小とし、代表は推定の距離が最大の点、同じなら小さい k)。
4. **谷ごとの確認とずらし** (生産の網 `N_p`、カードの `L_total_tol`): 代表 v で v と v ± 1 を評価する。
   - v が不成立 → その谷を捨てる。
   - v と両隣が成立 → その谷の最終の代表は v。
   - v が成立で片側だけ不成立 → 反対側へ 1 つずらす (移動先が同じ候補の区間にあるときだけ)。移動先で同じ確認を、その谷で最大 3 回まで繰り返す (初回の確認 + 移動 3 回)。区間の外に出る・両側が不成立・上限 → その谷を捨てる。
5. **谷の比較**: 最終の代表が決まった谷の中で、`N_p` の θ_max の全体の最小を θ_min とし、θ_max ≤ θ_min + 0.01° の谷を同点の集合として**一度だけ**作る (逐次比較しない)。
   その中で推定の距離が最大、同じなら θ_max が小さい、同じなら M_K が小さい谷を選ぶ。最終の代表が 1 つも無ければ例外 (表つき)。
6. 粗い網で成立点が無い・粗い網の長さ合わせが全点で未収束・候補が無いときは例外 (表つき)。黙って旧の規則に落ちない。

- 出す値は格子の値 (例 2.05)。
- **r_t の固定点と終了の条件**: 最初の r_t で 1〜5 を回して M_K を固定 → r_t の固定点 → 出力と**同じ実効の入力** (r_t・`n_axis_inv`・`L_total_tol`・`x_end_margin`・その他 geometry) で 1〜5 を回し直す。
  終了は「固定点の残差が許容内」かつ「その選択が使った M_K と一致」。違えば新しい M_K で固定点をやり直す (上限 2 回、超えたら例外)。
  自動調整 (`n_axis_inv` の倍化・`L_total_tol` の緩和: `wt_card.py:1706`、最終の壁の判定の後の `x_end_margin` の変更: `wt_card.py:2024`) が起きたら、それまでの評価を全部捨て、
  `N_s`・`N_p`・許容差・並列の数を設定し直して最初の選択からやり直す (今の `wt_card.py:2012` と同じ)。評価の使い回しは同じ実効の入力の中だけ。
- **計時**: M_knot に起因する再固定点・再評価の時間を全部 `M_knot_rule.elapsed_s` に入れる (今は `wt_card.py:1972` で加算の後に `solve_loop` を呼ぶので抜ける)。カード全体の時間も並べて記録する。
- 旧の規則 `min_theta_max_v1` の関数 (`select_mknot`・`resolution_gate`) と試験はモジュールに残す (カードからは呼ばない)。消すかは別に決める。

### 4.2 評価を軽くする (数値は変えない)

- **メモリ**: `evaluate_mknot` が `from_length` の反復で呼ばれた逆 MOC の結果 (網 `levels` を含む) を全部捕捉している (`mknot_select.py:164`)。`from_length` が正常に返すのは
  最後の評価 (plan 段レビューが 256 通りの残差系列で確認)。捕捉を最後の 2 つに限る (外を採ったら今と同じく行の `error` で不成立)。
- **並列**: 並列の数 = min(CPU 数, 4, ⌊0.7 × MemAvailable / 1 評価のピーク⌋)。ピークは捕捉の変更の後に `N_s`・`N_p` で測り直した値で持つ。算出が 0 なら評価の前に例外、
  MemAvailable が取れなければ 1。環境変数 `FORGE_MKNOT_WORKERS` で上限を下げられる (手元の PC の事故 2026-10-14 の再発防止)。

### 4.5 JIT の簡素化 (2026-10-15 ユーザ決定「処理が複雑化する懸念があり、下記の修正盛り込みたい JIT対応のあと。bit一致に特に意味がないとも思っています」)

最初の組み込み (§5.1 #4、commit は §9) は numpy の版と**ビット同一**にするため、(a) `np.interp` の C 実装 (二分探索の推測を含む) の写しと
(b) ν→M の Newton を numpy の版と同じ集合について**配列全体**で止める約束、(c) 集計 (`MocFillDiag.add`) の numba での書き直し (約 150 行)
を抱えていた。カーネルは約 650 行で、単位過程や集計を変えるたびに 2 か所を直す必要がある。ユーザ決定でこれを外す:

1. **ビット同一をやめ、許容差で照合する** (§6 V5 の許容差のまま)。ν→M の CPG の Newton は**対ごとに**止め、**前の反復の M から始める**
   (同じ |ΔM| < 1e−13・上限 60 回; **収束しなければ numpy の版と同じ初期値でやり直す** — 2026-10-15 に欠陥を見つけて追加、§6.5)。表の補間は素直な二分探索と線形の式 (範囲外は端の値、NaN は NaN)。
2. **集計を Python に戻す**: numba は段のループと数値だけを計算し、段ごとの対の状態 (分類の前の生の状態)・反復回数・最終残差・
   源項の分岐・新点の x・r・軸より下の印を返す。Python 側は既存の `MocFillDiag.add` を段ごとにそのまま呼ぶ (集計の実装は 1 つ)。
3. 速度の見込み (手元の実測、放射源流 n_ax 2400・analytic + converge): numpy の版 7.9 s、ビット同一の numba の版 4.0 s
   (Newton を配列全体で毎回同じ初期値から回すのが支配的)、`MocFillDiag.add` の段ごとの呼び出しは計 0.49 s。
   前の M から始める Newton で numba の部分が縮む見込み (受入は §6 V5 の「3 倍」のまま、AWS A で測る)。
4. 既存の試験 `run_moc_axis_limit_tests.py` の 8 (実装前のコードとのビット同一) は **numpy の版**の後方互換の試験として残し、新しい側を
   `FORGE_MOC_KERNEL=numpy` で回す。numba の版と numpy の版の照合は `run_moc_jit_tests.py` (V5) が許容差で受け持つ。
5. 生産の既定 (analytic + converge) の壁は numpy の版と丸めの範囲で違う (V5 の許容差 ≤ 1e−10 r_t で縛る)。legacy + fixed2 の
   「従来とビット同一」(plan discretization-moc-axis-limit-and-corrector) は numpy の版についての保証になる。

### 4.6 充填以外を削る (2026-10-15 ユーザ依頼「充填以外の 2〜3 割を削る … まず N 2400 の 1 評価を numba の版でプロファイルし直して、残りの内訳を見るのが先です」「まだ下げる余地があれば、こちらをやっていってほしいな」「AWS B使ってもいいんだよ」)

§6.3 のプロファイルで、JIT の後の 1 評価は充填以外が過半。**測り直し** (2026-10-15、BLAS 1 スレッド・負荷なし = 生産の worker と
同じ条件、cProfile 下): (a) case/70 c2b (逆 MOC 3 回) 8.2 s = 単位過程 (numba) 4.0 s・網の検査 1.4 s・`cplus_flux_wall` 0.7 s・
集計 0.5 s・軸則の評価と初期線 約 0.5 s・配列の確保 0.25 s; (b) case/71 (1 回) 4.0 s = 単位過程 1.4 s・網の検査 1.5 s・`cplus_flux_wall`
0.2 s・集計 0.2 s。§6.3 の `joint_fit_wall` 2.2 s は、裏で走っていた試験と BLAS のスレッドを取り合った測定の誤りで、負荷が無ければ
0.21 s (有効制約法 5 回・0.016 s)。**計時は負荷の無い機械で BLAS 1 スレッドで行う**。

やること (受入は次の 2 種類で、先に登録する):

- **出力が完全一致** (数値を変えない、同じ演算・同じ順序): (1) 集計 `MocFillDiag.add` (分類の数を `np.bincount` 1 回に、反復回数の
  分布も `bincount`、該当の無い分類は飛ばす。**済み** 2026-10-15、試験は高速化前の書き方の写しを参照にして `last_diag` が辞書の順・型まで
  完全一致、42 通り)。(2) 網の検査 `characteristic_topology_diagnostics` (n² 個の三角形の配列演算・段ごとの KD-tree): 返す辞書の数値と
  判定が完全一致。ただし点の堆積の位置の一覧 `pileup_locs_interior` (先頭 20 件、記録だけ) は KD-tree の対の集合の反復順で並んでいる
  ので、並びは変わってよく、集合 (と件数) が同じことを見る。**改訂 (2026-10-15 result 段 m3)**: 契約を「記録の代表 20 件は段・添字の順の
  先頭 20 件 (以前は集合の反復順なので、20 件を超えると選ばれる 20 件は以前と違う)」と明記し、試験は**切り詰める前の対の全集合**を、以前の
  書き方と同じ判定の cKDTree の参照と比べる。(3) `cplus_flux_wall`: C⁺ 線ごとのループを配列演算にまとめる (累積和は線に
  沿って同じ順序) — 壁の表が完全一致。
- **許容差** (§6 V5 と同じ形: numpy の版と比べて網の位置 ≤ 1e−10 r_t、θ/ν ≤ 1e−10 rad、壁 ≤ 1e−10 r_t、θ_max ≤ 1e−8°、判定の欄と集計の
  分類の数が同じ): (4) 単位過程の超越関数の呼び出しを減らす — sin μ = 1/M (μ = arcsin(1/M) なので数学的に同じ)、同じ角の tan と cos を
  sin・cos から作る、など。式の意味は変えない。

各段で N 2400 の 1 評価を測り直す。L_c の使い回し (#6、逆 MOC の回数を 1/3 にする) は plan 段 jit の M1 で後回しにしたままで、
ここではやらない (再開するならユーザに諮る)。
計時は AWS B で行う (ユーザ了承 2026-10-15; A は他セッションが CPU を使っている)。受入は §6 V5 の「N 2400 の 1 評価が 3 倍以上」のまま。
