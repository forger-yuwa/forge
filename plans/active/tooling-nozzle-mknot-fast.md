## 1. 目的

要求カードの M_knot の自動選択 (既定) は、1 枚の生成に 45〜97 分かかる (AWS、評価の並列 1/1; plan mknot-auto §5.1 #6)。パラスタのたびにこの時間がかかると使えない
(ユーザ 2026-10-15「パラスタする度に時間かかっちゃうならしんどい」「劇的に早くしてほしい」)。
**目標**: 選び方の規則は変えずに、カード 1 枚の M_knot の部分を 10 分以下 (目安は数分) にする。選ぶ網を粗くすると、平らな谷の中で選ぶ値は動きうる (600 の最小 2.04、2400 の最小 2.07)。合否は「生産の網で成立し境目から ΔM_safe 以上、θ_max の差が谷の中に収まる」(§6 V3) で決める。

## 2. スコープ

- **やる**: 評価の並列 (AWS で自動)、評価の回数の削減 (粗い当たり → 詰め、パラスタの暖機)、逆 MOC の 1 評価の高速化 (プロファイルで決める)、探索と最終設計の分離 (パラスタ用の経路)。
- **やらない**: 選び方の規則 (制約・境目からの距離 0.05・同点の規則・解像度のゲートの合否の式) の変更。試験 (n)(o) (2N にだけある境目) の緩和。

## 4. 設計方針 (2026-10-15 起案、上位に諮る前)

### 4.1 二層の網: 選ぶ網と作る網を分ける (ユーザ 2026-10-15「そもそもが、もっと荒くていいのでは」「規則というかメッシュのつもり」)

- **選ぶ網** `N_s` (既定 = 生産の `n_axis_inv` / 4、2400 なら 600) で、今の `select_mknot` と `resolution_gate` を**そのまま**回す。規則 (制約・境目の二分法・ΔM_safe 0.05・同点の規則)、
  窓の拡張、窓の外の文脈、settled の判定は変えない。ゲートの 2 倍の網は `2N_s` (1200)。変わるのは評価の関数に渡す `n_axis_inv` と `L_total_tol` だけ。
- **選ぶ網の長さの許容差** `L_s` = max(カードの `L_total_tol`, 0.05 r_t) (0.05 で未収束が出るなら 0.1; §5.1 #1b の測定で決める)。長さの誤差は θ_max の値に効く
  (見積もり dθ ≈ θ·dL/L、case/71 で 0.1 r_t / 80 r_t × 15° ≈ 0.02°) が、谷の中の θ_max の差はもともと小さく、選ぶ値を決めるのは境目からの距離。
- **作る網での確認 (新)**: 出力する値 `chosen_N` について、生産の網 `N_p` (カードの `L_total_tol`) で `chosen_N ± ΔM_safe` を fine (0.01) 刻みで 11 点評価し、全点が成立すること。
  1 点でも不成立なら「選ぶ網での選択は使えない」として、その組に限って今の方式 (`N_p`/`2N_p`) に落ちる (記録に残す)。これで、壁を作る網で選んだ点から ΔM_safe 以内に
  境目が無いことを、今の方式の窓と同じ 0.01 の粒度で確かめる。`2N_p` (4800) は既定では評価しない: 壁は `N_p` で作り、4800 の網は使わない。
  網に対する選択の頑健さは `N_s`/`2N_s` のゲートが受け持つ。
- r_t の固定点 (最初の r_t で選ぶ → 最終の組でゲートし直す、最終の組で最初の r_t のゲートを使い回さない) は今のまま。最終の組でも `N_s`/`2N_s` のゲートと `N_p` の確認を行う。
- 記録: card_log の `M_knot_rule` に `N_s`・`L_s`・`N_p` の確認の 11 点の行・フォールバックの有無を足す。

### 4.2 並列

- 並列の数は、使えるメモリ (MemAvailable の 7 割) / 1 評価の見積もり と CPU 数の小さい方 (上限 4)。見積もりは実測の最大 ((b) の 4800 の 5.6 GB) に合わせて係数を直す。
  手元の PC の事故 (2026-10-14) の再発を防ぐため、環境変数 `FORGE_MKNOT_WORKERS` で上限を下げられるようにし、既定の上限は AWS (g5.xlarge 4 vCPU・16 GB) を前提にする。
- `_mknot_mem_check` は「並列の数 × 1 評価」で判定する。

### 4.3 やらないこと・後回し

- 逆 MOC の内部点の計算 (`interior_vec`) の JIT 化: 時間の 6〜7 割だが、生産の壁を作る経路の数値が丸めの範囲で変わるので、別の受入 (同じ入力で壁の差の上限) が要る。#4 に分ける。
- パラスタの暖機 (前の点の M_K から始める): 4.1 で 1 枚が数分になるなら不要。パラスタの間は `overrides: {geometry.M_knot: <値>}` で固定し、最後の候補だけ自動にする手順を skill に書く (#5)。

(当初の候補の記録:候補: (1) 並列を使えるメモリと CPU 数から自動で決める (`_mknot_mem_check` と組み合わせる、手元の PC の上限は残す)、(2) 粗い解像度の当たり → 2400 の全部の局所極小と全部の境目を含む窓で詰める、(3) パラスタでは前の点の M_K から窓を始める、(4) 逆 MOC の 1 評価の高速化、(5) パラスタの間は M_K を与え最終の候補だけ自動選択、
(2′) **探索とゲートの逆 MOC の網を粗くする** (ユーザ 2026-10-15「そもそもが、もっと荒くていいのでは」「規則というかメッシュのつもり」): 今は探索に生産の網 (`n_axis_inv` 2400、雛形 `axismach_explore_v1`) を使い、ゲートは 2N = 4800。探索とゲートを 600/1200 程度の網で行い、生産の 2400 では選んだ点と前後 ±ΔM_safe だけを確かめる形。#1 の 600 と 2400 の比較 (境目・最小の位置) で可否を決める。最有力。
(6) 規則そのものを粗くする (呼び出し側の案。ユーザの発言は網のことで、規則の変更は求められていない; 優先度は低い)。根拠の候補: case/70 M5 の掃引の表 (測定のエージェントが読んだ記録、出典は #1 の報告で確定する) では、成立域 M_K 1.97〜2.20 の全体で θ_max は 15.288〜15.332° (幅 0.045°)、2.00〜2.10 では幅 0.006°。一方 n_axis_inv 2400 と 4800 の θ_max の差は 0.001〜0.002° で、0.01 刻みの詰めが並べている差と同じ大きさ。つまり 0.01 の詰めと 1e−3 の二分法は離散化の誤差の中で順位を付けている。設計に効くのは成立域の境目 (ここでは 1.97) からの距離の方なので、「境目を精密に求める」代わりに「粗い格子で境目から大きめの余裕を取り、選んだ 1 点 (と前後) だけを N・2N で確かめる」形が候補。2N にだけある細い不成立の島 (試験 (n)(o)) を粗い格子がどこまで拾えるかが論点。)
