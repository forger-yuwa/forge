## 1. 目的

case/45 の冷却壁 (300 K) の NS 格子 (ni 4719 × nj 121、`problem_d155_ns_prod_coldmesh{,_tw300}.yaml`) は、半径方向を壁から軸まで 1 本の等比 (比 1.07〜1.11) で張っている。
境界層に 84〜100 節点を使い、主流には 21〜37 節点しか残らない。軸の第 1 間隔は 0.10〜0.69 r_t (0.068〜0.100 r_w) で、縮流部〜スロートの軸際では dr/dx が 60〜72 になる。
ユーザ (2026-10-10):「格子が、軸周りが粗すぎる。細かくしすぎもよくないけど、粗すぎだと思う」「壁近くの中は 1.2〜1.3 倍、主流はもっと緩やかでいい」「減らないならやる意味ない」。

本 plan では、壁近くの比を 1.2〜1.3 に上げ、主流と軸付近の間隔に上限を付けた格子を作る。節点を減らしつつ (−38 %) 軸付近を細かくし、θ_r・δ・Q_w・軸と出口の M がどれだけ動くか、水準までの総時間が短くなるかを測る。そのうえで生産の格子を置き換えるかを決める。

## 2. スコープ

- **やる**:
  - 既存の `axis_cap_frac` (上限 c を固定し、列ごとに比を解く) で半径方向の分布だけを変える (§4.2)。メッシャのコードは変えない。x の station・第一セルの表・壁法線の層は今の格子と同じにする。
  - 候補の格子と比較用の格子を作り、品質・第一層・壁・格子線の折れを確かめる。
  - 300 K の腕で、今の格子・候補・比較用の 2 本を同じバイナリ・同じ起動・同じ設定で水準まで回して比べる (§4.4・§4.5)。
  - 1 step の時間と水準までの step 数を測り、総時間を比べる。
- **やらない**:
  - 縮流部の上流の x 方向を粗くする案。今の 1 ブロックの位相では壁の AR の上限に反する (§4.1)。
  - 断熱の腕・凝縮の腕。300 K の結果を見てから決める。
  - 軸の M の超過の原因追及 (verification-m6-axis-wave-mesh-su2 §5.1 #17)。本 plan の格子系列は #17 の候補 (a) のデータになるので、軸の値は記録して渡す。
  - 壁の作り直し (δ の反復)。壁は今の格子と同じ物理壁に固定する。
  - 生産の格子の置き換え。§6 の判定が出て、ユーザが決めるまで今の格子を生産とする (元のセッションが今の格子で float 化を検証している)。
  - FP64・node・軸対称の 300 K の結果を、float32・cell・周期のケースへ一般化すること (codex plan 段)。

## 4. 設計方針 (codex 諮問 2 回・plan 段 1 回を反映、2026-10-10)

### 4.1 x 方向を 3〜5 倍粗くする案を採らない理由

- 今の格子は 1 ブロックの H 型で、列 i の x の間隔は壁から軸まで共通である。x∈[−12, 12.5] では、その間隔が壁の AR (目標 4500) で決まっている (§3.1)。
- 縮流部の上流の x を 3〜5 倍粗くすると、壁の AR は 1.2〜2.3 万になり、AGENTS.md の上限 (壁法線の構造層で 5000) を超える。第一セルを厚くする余地も無い (y₁⁺ 0.7〜0.8、目標 0.8)。
- AR の余裕は最大 AR 4573 に対して 5000/4573 ≈ 1.09 倍しかない。x を少し粗くすることまで不可能なわけではないが、提案された 3〜5 倍には届かない。本 plan は半径方向だけを変える。
- **その後のユーザ決定 (2026-10-10)**: 壁際の AR の上限を 1 万に緩めた格子 G1x を、本 plan の試験として作る (§4.12)。AR ≤ 5000 の規則そのもの (AGENTS.md) は、G1x が §4.5 の判定に通ってから改めて提案する。
- 主流だけ x を粗くするには、位相を変える必要がある (主流を粗い x のブロックにし、四角形の遷移テンプレートか三角形でつなぐ)。forge は非適合の界面 (hanging node) を扱わない。node の双対 CV で遷移セルを入れた軸対称の格子は検証例が無い。費用と危険に対して利得を確かめていないので、本 plan では扱わない。

### 4.2 半径方向の分布 (上限 c を固定し、列ごとに比 q_i を解く = 既存の `axis_cap_frac`)

各列 i で、壁から k 番目の間隔 (/r_w、壁法線の層で変形する前) を

  g_k = min(f_i·q_i^k, c)    (k = 0, 1, …, nj − 2)

とし、Σ_k g_k = 1 になるように比 q_i を列ごとに解く (`mesh2d._radial_fracs_capfixed`、二分法)。f_i は今の第一セルの表 (`wall_first_frac_table`) の値、c は主流と軸付近の間隔の上限 (`axis_cap_frac`) である。

- **nj の決め方**: 全列で q_i ≤ q_max になる最小の nj。第一セルが最も薄いスロートの列で決まり、ほかの列では q_i < q_max になる (余った節点は境界層に回る)。`generate_axisym_mesh` は解いた比を捨てる (`mesh2d.py:209`) ので、`core_grid_mesh.py select` が同じ関数で全列の q_i を取り直して確かめる。
- **c は変形前の分布のパラメータであり、物理的な間隔の上限ではない** (codex plan 段 M3・2 回目の諮問)。壁法線の層 (`mesh2d.py:232–244`) は分布を作った後に座標を動かすので、つなぎ目では半径方向の辺が c·r_w を最大 25 % 超える (G1 で 0.0375 r_w)。軸から 5 本の範囲は変形しないので c·r_w のまま。変形後の格子は §5.1 #3 で全域を検査する。
- メッシャのコードは変えない (`prepare_ns` は `axis_cap_frac` を第一セルの表・壁法線の層と一緒に渡す、`runner_axismach.py:695`)。
- **経緯**: 初稿は逆の形 (比 q_w を全列で固定し、上限 c_i を列ごとに解く) だった。ユーザの「壁近くは 1.2〜1.3 倍、主流はもっと緩やか」をそのまま式にしたものである。しかしこの形では c_i が第一セル厚 f に敏感で (dc/df ≈ −1.4〜−1.7 万)、f が x で急に変わる入口〜縮流部で主流の節点が列ごとに動き、格子線が最大 20.9° 折れた (§4.9)。後縁の冷点が格子線の 36° の折れから出た前例がある (case/46 SERN)。上限を固定する形では主流の節点が η = j·c に固定されるので、この経路が無い。
- **比の上限 q_max は 1.3** (2026-10-10 ユーザ「壁際の比も 1.2〜1.3 って言ったつもりだった」)。最初は 1.2 にしていた (nj 92、比 1.12〜1.20)。節点数はスロートの列で決まり、ほかの列の比を上げても余った節点が主流に回るだけで節点は減らないので、スロートの列の比を 1.3 に上げた。全列の比は 1.18〜1.30 になり、ユーザの「壁近く 1.2〜1.3」にほぼ一致する。
- 見積もりの段階では、主流の比を 1.03〜1.05 にする 3 段の形 (壁近く → 緩い比 → 一様) も試したが、節点が今と同程度か増えた (nj 101〜146)。ユーザ「減らないならやる意味ない」「1.2 倍で伸ばす領域を大きくしたらいい」(2026-10-10) を受けて外した。

### 4.5 量と判定

- **量** (各腕の到達後の窓の最後の出力で取る):
  - θ_r・δ_loc: **x の窓 [40, 50]・[65, 75]・[84, 94] の平均** (台形の線平均)、断面の分布は **PCHIP でつなぐ** (`cold_xcheck.reduce_fields(profile="pchip")`)。点の値 (x = 40・70・94) と折れ線 (既定) の値は記録だけ (§4.10: 点の値と折れ線は、同じ連続の場でも格子で 0.1〜0.7 % 動く)。
  - Q_w (`cold_xcheck.reduce_fields`、既定のまま。後処理の格子依存は 0.02 % 以下、§4.10)
  - 出口の主流 M: 最終断面の **η∈[0.05, 0.7] の線平均 ∫M dη/0.65** (端点は補間)。今の `nozzle_report.metrics` の節点の単純平均は、同じ M(η) を載せても格子の間で最大 0.0056 % 変わるので使わない (§4.6)。
  - 軸 (η = 0) と η = 0.1 の 100(M/6 − 1): 試験部の窓 x∈[x_E + 2, x_F − 1] の平均と、超過 (窓 x∈[x_E − 15, x_F] の最大)。今の `metrics` は平均を返さないので足す。
  - 壁の y₁⁺ (`check_wall_resolution.py --groups wall --weight area`): y₁⁺ > 1 の面積の割合と位置、最大値。第一層の座標が同じでも、壁の応力が変われば y₁⁺ は変わる (codex plan 段 M3)。
  - 記録だけ (判定に使わない): 波 (10 r_t の P-spline からの残差の最大)・試験部の傾き、ṁ_in・ṁ_out・欠損、本段の `check_convergence` の VERDICT。
- **相対差の分母**は G0′ の値 (2026-10-10 諮問で改めた。G2 は回さない)。キー 0/1 の比較は同じ格子のキー 0。量に非有限・欠測があれば J0 で判定不能。
- **許容差 τ** (それぞれ独立の要求。換算での正当化はしない): δ_loc 1 %、θ_r 1 %、Q_w 1 %、出口の主流 M 0.02 %、軸・η = 0.1 の平均と超過 0.02 %pt。
- **時間変動の不確かさ u**: 各腕・各量で、到達後の窓 (4 万 step、17 出力) の中の最後の値からのずれの最大。時間変動の幅であり、未収束の偏りの上限ではない。
- **反復条件の感度 s**: §4.4 の point の継続 4 万 step の前後の差の絶対値。
- **後処理の予算 p**: 同じ連続の場を各格子に載せたときの、後処理だけの誤差 (§4.10 の表、真の分布 2 通りの最大)。
- **判定の順序**:
  - J0 (判定できるか): 2 本とも本段で水準に到達し、到達後の窓と反復条件の感度の run が揃い、判定の全量で `check_quasisteady.py` の VERDICT が STEADY (到達後の窓)、u ≤ τ/4、非有限なし。`check_convergence` が DIVERGED の腕は比較不可。後処理 (`cold_series`・追加した `metrics`) は既知の分布により確認済み (§4.10)。満たさなければ「判定不能」で上位に諮る。単調な STEADY の量は漸近値も併記する。
  - J1 (候補の採用の可否): 判定の全量で
    |G1 − G0′| + u_G1 + u_G0′ + s_G1 + s_G0′ + p_G1 + p_G0 ≤ τ
    (2026-10-10 ユーザ決定で G0′ と G1 の 2 本に絞った。Gc を経由する経路の和は使わない)。
    かつ G1 の壁解像が y₁⁺ > 1 の面積 ≤ 1 % (G0 は 0.5 %)・最大 ≤ 1.5 (G0 は 1.36)。
    かつ G1 の水準到達までの時間の上限が G0′ の下限より短い。
    → G1 を生産の候補としてユーザに諮る。結論は「今の格子と許容差内で同じ答え」であり、「格子収束した」ではない。
  - **G1x** (§4.12) にも J1 を同じ形で当てる (|G1x − G0′| + u + s + p ≤ τ、壁解像、時間)。p は θ_r・δ_loc が G1 の値 (窓 x∈[40, 94] では x の間隔も半径方向の分布も G1 と同じ)、Q_w が 0.06 % (G1 の 0.028 % に x の粗さによる積分の差 0.032 % を足した)。G1 が通り G1x だけ外れたら、x を粗くしたことが原因と読める。どちらも通れば節点の少ない G1x を候補にする。
  - J2 (G1 が許容差を外れた): 量ごとに符号付きの差 G1 − G0′ と、各格子の c・q_i の分布を示す。軸の M の量は G0 の軸付近が粗いことがそもそもの問題 (§1) なので、差が出ても G1 が悪いとは限らない。どちらが正しいかを決めるのに細かい格子 (準備済みの Gc・G2) を回すかを、ユーザと上位に諮る。
  - J3 (速さ): 時間の区間が重なったら「判定不能」。G1 の下限が G0′ の上限以上なら、節点を減らした意味が無いので採らない (ユーザ「減らないならやる意味ない」)。
  - J4: 上のどれにも当たらない → 上位に諮る。
- **時間の上下限** (codex plan 段 m6): 腕ごとに T = Σ_段 N_段·t_段 + n_出力·t_出力 + t_起動。**読み方** (2026-10-10 諮問): 移送の過渡を含む「run_0183 から各格子を水準に持っていく運用の費用」であり、格子の一般的な収束の速さとは呼ばない。並行実行の経過時間は使わない。
  - t_段 は GPU 専有で各格子 1000 step × 3 (G0′ と交互) の最小・最大 (soft・mid は 1 次の構成で別に測る)。
  - 本段の N は水準を検出した出力 N_r に対し、下限 N_r − 2500、上限 N_r (出力の間隔の分)。
  - t_出力・t_起動 はログの時刻から各腕で測る (最小・最大)。
  - 下限 = 各項の下限の和、上限 = 各項の上限の和。
- **NOT CONVERGED の扱い** (1 回目の諮問と plan 段 M1 の結論): `check_convergence` の NOT CONVERGED を一律の失格にはしない (今の格子の run も NOT CONVERGED で、ユーザは終わりの基準を水準だけにすると決めている。time_integration-line-implicit-speed §6.15)。ただし「今も未収束だから注記だけで通す」もしない。生産の候補にするには、J0 の STEADY と J1 の反復条件の感度 s の予算を満たす必要がある。s を測っていなければ J1 は保留する。
